本章节定义 SDK 互联互通的 MOP 数据通道 MQTT 控制面接口，涵盖启用通道、关闭通道与通道状态推送的 payload 结构与字段说明。

MOP 数据通道采用双平面架构：MQTT 接口为控制面，负责协商目标设备与通道参数、返回 TCP 数据面端点、并推送通道状态；实际业务数据经数据面的 TCP socket 收发，不经 MQTT。控制面双向交互：负载发起启用 / 关闭通道的 service 命令，飞机通过 event 推送通道状态。

:::tip 说明：
- PSDK 中的 C 接口是对本章节 MQTT 协议的封装。使用 PSDK 开发时，无需直接操作 MQTT 报文；如需自行实现协议对接，或对底层消息进行调试验证，可参照本章节的协议定义。功能介绍与 C 接口调用示例详见 <a href="../function-set/sdk-interconnection.html" target="_blank" rel="noopener noreferrer">功能集合-SDK 互联互通</a>。
- 使用本功能前，负载设备需先完成接入与鉴权，接入协议详见 <a href="api-access-authentication.html" target="_blank" rel="noopener noreferrer">接入与鉴权</a>。
:::

:::warning 注意：
MOP 数据面基于 POSIX TCP socket，仅支持 Linux 平台，且需飞机固件支持 MOP 通道。本章仅定义控制面的 MQTT 协议，数据面的 TCP 连接与收发由负载自行实现。
:::

## 协议说明

接口涉及的 Topic 如下：

| 类型 | 方向 | Topic |
|:---|:---|:---|
| service 请求 | 负载 → 飞机 | `thing/product/{client_id}/services` |
| service 响应 | 飞机 → 负载 | `thing/product/{client_id}/services_reply` |
| event 推送 | 飞机 → 负载 | `thing/product/{client_id}/events` |

- `{client_id}` 为负载设备序列号（device sn）。
- **QoS**：0。

本模块支持的接口如下：

| method | 类型 | 用途 | 对应 C 接口 |
|:---|:---|:---|:---|
| `mop_channel_enable` | service | 负载启用数据通道，获取 TCP 数据面端点 | `MopChannel_Enable()` |
| `mop_channel_disable` | service | 负载关闭数据通道 | `MopChannel_Disable()` |
| `mop_channel_event` | event | 飞机向负载推送通道状态（ACTIVE、CLOSED） | `MopChannel_OnChannelEvent()` |

:::warning 注意：
完整通道生命周期：负载发 `mop_channel_enable` → 飞机回 `ip` / `port` / `state:"listening"` → 负载建立 TCP 连接 → 飞机推送 `mop_channel_event`（state=1 ACTIVE）→ 数据面收发 → 负载发 `mop_channel_disable` → 飞机推送 `mop_channel_event`（state=2 CLOSED）→ 负载关闭 socket。通道 ID 不限制固定取值范围，两端约定使用同一个通道号即可建立通信。
:::

## 公共参数

以下参数为 MOP 各接口消息共用的顶层通用参数，各接口的字段说明中不再重复列出。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| seq | integer | 是 | 请求序列号；响应原样回显，用于请求与响应匹配。 |
| method | string | 是 | 方法标识，取值见各接口说明。 |
| data | object | 是 | 业务数据主体；无业务参数时为 `{}`。 |

### 响应参数

响应顶层字段与请求一致。各接口的 `data` 字段见对应小节。

## 启用通道

负载启用数据通道。飞机在响应中返回通道状态与 TCP 数据面端点（ip / port），负载据此建立 TCP 连接。

对应功能介绍：<a href="../function-set/sdk-interconnection.html#启用通道" target="_blank" rel="noopener noreferrer">启用通道</a>。

### 请求 Payload 示例

- **Topic**：`thing/product/{client_id}/services`
- **方向**：负载 → 飞机
- **QoS**：0
- **method**：`mop_channel_enable`
- **对应接口**：`MopChannel_Enable()`

```json
{
  "seq": 1,
  "method": "mop_channel_enable",
  "data": {
    "role": 1,
    "reliability": 0,
    "channel_id": 49153,
    "target_device_type": 3,
    "target_address": 1
  }
}
```

### 请求字段说明

顶层字段见 [请求参数](#请求参数)，`data` 字段说明如下：

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| role | integer | 是 | 通道角色。<ul><li>0：ROLE_SERVER，监听等待对端连接</li><li>1：ROLE_CLIENT，主动连接对端</li></ul> |
| reliability | integer | 是 | 数据面传输类型。<ul><li>0：RELIABILITY_RELIABLE，可靠传输</li><li>1：RELIABILITY_UNRELIABLE，非可靠传输</li></ul> |
| channel_id | integer | 是 | 通道 ID，两端约定使用同一个通道号即可建立通信。 |
| target_device_type | integer | 是 | 目标设备 SDK 类型。<ul><li>1：TARGET_DEVICE_TYPE_MSDK，移动端</li><li>2：TARGET_DEVICE_TYPE_OSDK，机载</li><li>3：TARGET_DEVICE_TYPE_PSDK，负载</li></ul> |
| target_address | integer | 是 | 目标地址。<ul><li>client 模式：目标负载位置 1、2、3</li><li>server 模式：固定为 0</li></ul> |

### 响应 Payload 示例

- **Topic**：`thing/product/{client_id}/services_reply`
- **方向**：飞机 → 负载

```json
{
  "seq": 1,
  "method": "mop_channel_enable",
  "data": {
    "result": 0,
    "result_message": "success",
    "channel_id": 49153,
    "state": "listening",
    "ip": "192.168.1.1",
    "port": 12345
  }
}
```

### 响应字段说明

顶层字段见 [响应参数](#响应参数)，`data` 字段说明如下：

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| result | integer | 是 | 处理结果。<ul><li>0：成功</li><li>非 0：失败</li></ul> |
| result_message | string | 是 | 结果描述信息。 |
| channel_id | integer | 是 | 通道 ID。 |
| state | string | 是 | 通道状态，成功时为 `listening`。 |
| ip | string | 是 | TCP 数据面端点 IP 地址，负载据此建立 TCP 连接。 |
| port | integer | 是 | TCP 数据面端点端口。 |

## 关闭通道

负载关闭数据通道。service 响应为空，通道关闭以通道状态推送 `mop_channel_event`（state=2 CLOSED）为准。

对应功能介绍：<a href="../function-set/sdk-interconnection.html#关闭通道" target="_blank" rel="noopener noreferrer">关闭通道</a>。

### 请求 Payload 示例

- **Topic**：`thing/product/{client_id}/services`
- **方向**：负载 → 飞机
- **QoS**：0
- **method**：`mop_channel_disable`
- **对应接口**：`MopChannel_Disable()`

```json
{
  "seq": 2,
  "method": "mop_channel_disable",
  "data": {
    "channel_id": 49153
  }
}
```

### 请求字段说明

顶层字段见 [请求参数](#请求参数)，`data` 字段说明如下：

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| channel_id | integer | 是 | 待关闭的通道 ID。 |

### 响应 Payload 示例

- **Topic**：`thing/product/{client_id}/services_reply`
- **方向**：飞机 → 负载

```json
{
  "seq": 2,
  "method": "mop_channel_disable",
  "data": {}
}
```

### 响应字段说明

顶层字段见 [响应参数](#响应参数)，响应 `data` 为空对象 `{}`。通道真正关闭由 [通道状态推送](#通道状态推送) 下发 `CLOSED` 状态确认。

## 通道状态推送

飞机推送通道状态变化。通道就绪时推送 `ACTIVE`，通道关闭时推送 `CLOSED`。

对应功能介绍：<a href="../function-set/sdk-interconnection.html#接收通道状态" target="_blank" rel="noopener noreferrer">接收通道状态</a>。

### Payload 示例

- **Topic**：`thing/product/{client_id}/events`
- **方向**：飞机 → 负载
- **QoS**：0
- **method**：`mop_channel_event`
- **对应接口**：`MopChannel_OnChannelEvent()`

```json
{
  "seq": 3,
  "method": "mop_channel_event",
  "data": {
    "channel_id": 49153,
    "state": 1
  }
}
```

### 字段说明

顶层字段见 [请求参数](#请求参数)，`data` 字段说明如下：

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| channel_id | integer | 是 | 通道 ID。 |
| state | integer | 是 | 通道状态。<ul><li>1：ACTIVE，数据面就绪，可开始 TCP 收发</li><li>2：CLOSED，通道关闭，应安全关闭 TCP socket</li></ul> |

:::warning 注意：
`state` 为 1（ACTIVE）表示数据面就绪，负载可开始 TCP 收发；为 2（CLOSED）表示通道关闭，负载应安全关闭 TCP socket。若在等待 ACTIVE 期间收到 CLOSED，通常表示对端设备未就绪。
:::
