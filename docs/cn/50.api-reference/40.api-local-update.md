本章节定义本地升级（Upgrade）功能的 MQTT 接口，涵盖进入升级模式、校验固件、启动升级、完成升级与升级状态推送的 payload 结构与字段说明。

:::tip 说明：
- PSDK 中的 C 接口是对本章节 MQTT 协议的封装。使用 PSDK 开发时，无需直接操作 MQTT 报文；如需自行实现协议对接，或对底层消息进行调试验证，可参照本章节的协议定义。功能介绍与 C 接口调用示例详见 <a href="../function-set/local-update.html" target="_blank" rel="noopener noreferrer">功能集合-本地升级</a>。
- 使用本功能前，负载设备需先完成接入与鉴权，接入协议详见 <a href="api-access-authentication.html" target="_blank" rel="noopener noreferrer">接入与鉴权</a>。
:::

## 协议说明

接口涉及的 Topic 如下：

| 类型 | 方向 | Topic |
|:---|:---|:---|
| service 请求 | 飞机 → 负载 | thing/product/{client_id}/services |
| service 响应 | 负载 → 飞机 | thing/product/{client_id}/services_reply |
| event 推送 | 负载 → 飞机 | thing/product/{client_id}/events |

- `{client_id}` 为负载设备序列号（device sn）。
- **QoS**：0。

本模块支持的接口如下：

| method | 类型 | 用途 | 对应 C 接口 |
|:---|:---|:---|:---|
| upgrade_enter_upgrade_mode | service | 飞机请求负载进入升级模式 | UpgradeImpl_OnEnterUpgradeMode() |
| upgrade_check_firmware | service | 飞机请求负载校验固件 | UpgradeImpl_OnCheckFirmware() |
| upgrade_start_upgrade | service | 飞机指示负载启动升级 | UpgradeImpl_OnStartUpgrade() |
| upgrade_finish_upgrade | service | 飞机通知升级序列结束 | UpgradeImpl_OnFinishUpgrade() |
| upgrade_push_upgrade_state | event | 负载推送升级状态 | Upgrade_PublishPushUpgradeState() |

:::warning 注意：
升级命令存在严格时序：飞机依次下发 `upgrade_enter_upgrade_mode` → `upgrade_check_firmware` → `upgrade_start_upgrade` → `upgrade_finish_upgrade`。负载收到 `upgrade_start_upgrade` 后应立即应答，再后台执行升级并通过 `upgrade_push_upgrade_state` 持续上报升级状态，收到 `upgrade_finish_upgrade` 后停止推送。固件本体通过 HTTP 传输（由进入升级模式响应中的 `url` 提供），不经 MQTT 通道。
:::

## 公共参数

以下参数为升级各接口请求与响应共用的顶层通用参数，各接口的字段说明中不再重复列出。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| seq | integer | 是 | 请求序列号；响应原样回显，用于请求与响应匹配。 |
| method | string | 是 | 方法标识，取值见各接口说明。 |
| data | object | 是 | 业务数据主体；无业务参数时为 `{}`。 |

### 响应参数

响应顶层字段与请求一致。`data` 默认包含以下公共字段；接口特有字段见对应小节。

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| result | integer | 是 | 处理结果。<ul><li>0：成功</li><li>非 0：失败</li></ul> |
| result_message | string | 是 | 结果描述信息。 |

## 进入升级模式

飞机请求负载进入升级模式。负载应答中返回飞机需等待的秒数及固件下载地址，飞机据此通过 HTTP 获取固件。

对应功能介绍：<a href="../function-set/local-update.html#进入升级模式" target="_blank" rel="noopener noreferrer">进入升级模式</a>。

### 请求 Payload 示例

- **Topic**：`thing/product/{client_id}/services`
- **方向**：飞机 → 负载
- **QoS**：0
- **method**：`upgrade_enter_upgrade_mode`
- **对应接口**：`UpgradeImpl_OnEnterUpgradeMode()`

```json
{
  "seq": 1,
  "method": "upgrade_enter_upgrade_mode",
  "data": {}
}
```

### 请求字段说明

顶层字段见 [请求参数](#请求参数)，`data` 固定为空对象 `{}`。

### 响应 Payload 示例

- **Topic**：`thing/product/{client_id}/services_reply`
- **方向**：负载 → 飞机

```json
{
  "seq": 1,
  "method": "upgrade_enter_upgrade_mode",
  "data": {
    "result": 0,
    "result_message": "success",
    "wait_time": 10,
    "url": "http://192.168.1.10:8000/upgrade.bin"
  }
}
```

### 响应字段说明

顶层字段见 [响应参数](#响应参数)，`data` 字段说明如下：

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| wait_time | integer | 是 | 飞机应等待的秒数，用于负载准备存储区等前置操作。 |
| url | string | 是 | 固件下载地址，飞机通过 HTTP 从该地址获取固件，如 `http://<device-ip>:8000/upgrade.bin`。 |

## 升级状态推送

负载在升级执行期间推送当前升级状态，包含升级进度和结果。

对应功能介绍：<a href="../function-set/local-update.html#推送升级状态" target="_blank" rel="noopener noreferrer">推送升级状态</a>。

### Payload 示例

- **Topic**：`thing/product/{client_id}/events`
- **方向**：负载 → 飞机
- **QoS**：0
- **method**：`upgrade_push_upgrade_state`
- **对应接口**：`Upgrade_PublishPushUpgradeState()`

```json
{
  "seq": 5,
  "method": "upgrade_push_upgrade_state",
  "data": {
    "upgrade_stage": 3,
    "value": 50
  }
}
```

### 字段说明

顶层字段见 [请求参数](#请求参数)，`data` 字段说明如下：

| 字段 | 类型 | 必填 | 说明 |
|:---|:---|:---|:---|
| upgrade_stage | integer | 是 | 升级阶段。<ul><li>0：空闲，无升级进行</li><li>3：升级中</li><li>4：升级完成</li><li>6：设备重启中</li></ul> |
| value | integer | 是 | 含义随 upgrade_stage 变化。<ul><li>升级中（3）：升级进度，取值 0~100</li><li>升级完成（4）：升级结果，1 为成功，2 为失败</li><li>设备重启中（6）：重启超时秒数，取值 0~255</li></ul> |

:::warning 注意：
`value` 字段的含义依赖 `upgrade_stage`，解析时须先判断阶段再解释取值。升级完成阶段（4）的 `value` 为升级结果（1 成功 / 2 失败），不应与升级进度（0~100）混淆。
:::
