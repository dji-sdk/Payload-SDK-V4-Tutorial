Payload SDK 是一套基于 MQTT 协议的开源负载接入 SDK，面向自研负载和第三方负载接入 DJI 无人机平台的开发场景。开发者可通过 SDK 提供的 C 接口和参考实现，在负载固件或机载计算平台中实现业务逻辑，完成设备鉴权上线、控制交互、数据上报、远程升级等能力集成。

与封装为二进制库的接入方案不同，本 SDK 协议与源码完全开放，通信全过程透明、可裁剪、可自主移植；配套精简的运行时库、跨平台样例库与可插拔适配层，构成完整的负载接入开发套件。

> 运行时库（Runtime）：SDK 提供的核心支撑库，封装了 MQTT 会话管理、鉴权、编解码与内存管理等通用能力，随负载应用一起运行，开发者直接链接调用即可，无需自行实现底层通信逻辑。

借助 Payload SDK，开发者可以：

* 用统一的能力描述定义负载对外提供的服务、属性、事件与状态；
* 在负载本体（MCU / RTOS）或机载计算平台（Linux）上集成 SDK，实现设备侧能力；
* 通过标准 MQTT 通道与平台进行控制指令与数据的双向交互；
* 复用开放、可插拔的运行时库，无需自行实现 MQTT 协议栈、鉴权与编解码。

## 软件框架概览

SDK 采用分层设计，各层职责单一、边界清晰，开发者主要关注最上层的业务实现，底层通信由运行时库处理。

各层职责如下：

* **应用层**：开发者业务代码，实现负载的具体能力，如服务处理、状态采集与数据处理。
* **SDK 接口代码**：SDK 提供的 C 客户端与设备端代码，负责业务接口能力的开放。
* **运行时库 Runtime**：管理 MQTT 会话、鉴权（TLS + HMAC）、自动重连与订阅恢复、JSON 编解码与内存管理。
* **适配层**：传输（mosquitto / Paho）、加密（OpenSSL / mbedTLS）、操作系统（POSIX / RTOS）与内存分配均可替换，便于对接既有安全方案与硬件平台。
* **平台层**：通过 MQTT Broker 接入平台，与云端 / App 交互。

## 开发流程

从工程实施角度，负载接入遵循如下流程：
1. **定义能力**：定义负载的服务 / 属性 / 事件 / 状态的协议。
2. **集成运行时库**：在工程中引入运行时库与协议代码，注册 OS / 传输 / 加密适配。
3. **实现能力**：编写设备侧业务逻辑，处理服务调用、上报状态与事件。
4. **配置凭据**：填入 App 凭据（App ID / Key / License）、设备 SN 与 Broker 地址。
5. **联调上线**：连接 Broker 完成鉴权，验证控制与数据链路后正式上线。


## 两种部署形态

根据 SDK 的运行位置不同，负载开发分为两种部署形态。

### 负载本体开发（嵌入式 MCU / RTOS）

在负载设备的嵌入式控制器上直接运行 SDK（如 GD32F527 + FreeRTOS / lwIP / mbedTLS）。

* 贴近硬件，资源占用小，无需额外算力单元；
* 负载本体直接联网接入平台；
* 适合喊话器、自定义控件、传感器等负载本体。

### 机载计算平台开发（Linux）

在机载 Linux 计算平台（如妙算或通用 Linux 主板，支持 x86_64 / aarch64）上运行 SDK（如 Ubuntu + mosquitto / Paho + OpenSSL）。

* 算力充足，便于集成复杂业务逻辑与第三方库；
* 可承载多负载聚合与协同；
* 适合数据处理量大或业务逻辑复杂的场景。

## 两种形态的关系

* **独立部署**：负载本体或机载计算平台任一形态均可独立接入平台。
* **协同部署**：负载本体负责感知与执行，机载计算平台负责聚合、处理与转发，二者经机载链路协同，构成完整的负载业务系统。

```
负载本体（采集 / 执行）
    ↕ 机载链路
机载计算平台（聚合 / 处理 / 调度）
    ↕ MQTT
MQTT 平台（远程管理 / 数据汇聚）
```


## 如何选择开发方式

| 对比项 | 负载本体开发（MCU / RTOS） | 机载计算平台开发（Linux） |
| --- | --- | --- |
| 运行环境 | 嵌入式实时系统 | 机载 Linux（x86_64 / aarch64） |
| 算力资源 | 受限 | 充足 |
| 资源占用 | 小 | 中 |
| 第三方库集成 | 受限 | 灵活 |
| 典型负载 | 喊话器 / 控件 / 传感器 | 复杂业务 / 多负载聚合 |
| 适用场景 | 硬件本体直接联网 | 高算力 / 复杂数据处理 |

选型建议：

* 资源受限、功能单一、成本敏感 → 负载本体开发（MCU / RTOS）
* 算力需求高、业务复杂、需集成第三方库 → 机载计算平台开发（Linux）
* 多负载协同 / 统一网关 → 机载计算平台聚合 + 负载本体接入

> 以上为常见工程经验，实际选型还受负载形态、功能复杂度、成本与团队经验等因素影响。
