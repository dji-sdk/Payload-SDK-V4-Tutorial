## 概述

喊话器控件（Speaker）用于负载接收飞机下发的控制指令和音频文件，并周期上报自身状态。

飞机可下发工作模式、播放模式、音量设置、播放控制和音频传输命令；负载注册回调响应这些命令，并通过推送端上报当前状态。

:::tip 说明：
- PSDK 中的 C 接口是对底层 MQTT 协议的封装，开发者通过调用 C 接口即可完成协议交互，无需手动构造 MQTT 报文。底层 MQTT 协议的 payload 结构与字段定义详见 <a href="../api-reference/api-speaker.html" target="_blank" rel="noopener noreferrer">协议参考-喊话器控件</a>。
- 使用本功能前，负载设备需先完成接入与鉴权，详见 <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">接入与鉴权</a>。
:::

## 基础概念

### 名词解释

**喊话器命令响应端 (impl)**

负载侧用于接收并响应飞机下发的 8 个喊话器命令的对象。负载为每个命令注册一个处理回调，飞机下发对应命令时由 SDK 回调到负载。

**喊话器状态推送端 (publisher)**

负载侧用于主动向飞机上报喊话器状态的对象。负载周期通过该对象推送系统状态、工作模式、播放模式、音量及当前播放文件信息。

**工作模式与播放模式**

- 工作模式（work_mode）：`0` 为 TTS（文字转语音），`1` 为 voice（语音文件）。
- 播放模式（play_mode）：`0` 为 single（单次播放），`1` 为 loop（循环播放）。

**音频文件分包传输**

飞机向负载传输音频文件时，按「开始 → 数据包 → 结束」三阶段进行：
- `trans_start` 声明文件元信息。
- `trans_data` 逐包传输音频数据（传输时为 hex 编码，SDK 自动解码为二进制）。
- `trans_finish` 携带整文件 MD5 供负载校验。

### 音频传输时序

音频文件传输须严格遵循以下时序，负载侧回调按此顺序被触发：

1. **trans_start**：负载创建临时文件，记录 uuid 与文件名，进入传输态（system_state=1）。
2. **trans_data**：负载按 `offset` 将本包二进制数据写入临时文件；支持乱序与重传（按 offset 定位覆盖）。
3. **trans_finish**：负载关闭文件，计算 MD5 并与请求中的 `md5` 比对；一致则重命名为正式文件，否则通知对端重传。

:::warning 注意：
`trans_data` 请求中的 `data` 字段传输时为 hex 字符串，SDK 已自动解码为二进制（`T_ThingModelBytes`），回调中可按 `offset` 写入文件。MD5 校验失败时应返回非 0 结果通知对端重传；重传超过上限后，应终止传输并清理会话，避免流程长时间阻塞。
:::

## 功能介绍

:::warning 注意：
以下代码为参考示例，用于说明各功能的调用流程与实现方式。开发者可结合负载设备的硬件特性和应用场景进行适配。

### 创建响应端与推送端

在已建立的 MQTT 会话 `s` 上创建喊话器命令响应端与状态推送端，后续命令回调通过响应端注册，状态推送通过推送端发出。

```c
SpeakerImpl_t      *spimpl = SpeakerImpl_Create(s, device_sn);
Speaker_Publisher_t *sppub  = Speaker_CreatePublisher(s);
```

### 设置工作模式

注册「设置工作模式」回调。飞机下发该命令时，负载在回调中更新工作模式（TTS / voice）并返回结果。对应的 MQTT 协议见 <a href="../api-reference/api-speaker.html#设置工作模式" target="_blank" rel="noopener noreferrer">设置工作模式</a>。

```c
static T_ThingModelReturnCode on_set_work_mode(SpeakerImpl_t *impl, void *user,
        const T_SpeakerSetWorkModeRequest *req, T_ThingModelCommonReply *reply)
{
    AppSpeaker *app = user;
    app->work_mode = req->work_mode;
    reply->result = 0;
    snprintf(reply->result_message, sizeof(reply->result_message), "success");
    return THING_MODEL_RC_OK;
}

SpeakerImpl_OnSetWorkMode(spimpl, on_set_work_mode, &sp);
```

:::tip 说明：
`T_ThingModelCommonReply` 的 `result_message` 为定长字符数组，应使用 `snprintf` 填写，不应使用 `strdup`。
:::

请求结构 `T_SpeakerSetWorkModeRequest` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| work_mode | int32_t | 工作模式：0 TTS（文字转语音）/ 1 voice（语音文件） |

### 设置音量

注册「设置音量」回调。飞机下发该命令时，负载在回调中校验并更新音量。对应的 MQTT 协议见 <a href="../api-reference/api-speaker.html#设置音量" target="_blank" rel="noopener noreferrer">设置音量</a>。

```c
static T_ThingModelReturnCode on_set_volume(SpeakerImpl_t *impl, void *user,
        const T_SpeakerSetVolumeRequest *req, T_ThingModelCommonReply *reply)
{
    AppSpeaker *app = user;
    if (req->volume < 0 || req->volume > 100) {
        reply->result = -1;
        snprintf(reply->result_message, sizeof(reply->result_message), "volume out of range");
        return THING_MODEL_RC_OK;
    }
    app->play_volume = req->volume;
    reply->result = 0;
    snprintf(reply->result_message, sizeof(reply->result_message), "success");
    return THING_MODEL_RC_OK;
}

SpeakerImpl_OnSetVolume(spimpl, on_set_volume, &sp);
```

请求结构 `T_SpeakerSetVolumeRequest` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| volume | int32_t | 音量，取值范围 0~100 |

注册「开始播放」回调。飞机下发该命令时，负载在回调中启动播放并将状态置为 playing。本接口无 data 入参。对应的 MQTT 协议见 <a href="../api-reference/api-speaker.html#开始播放" target="_blank" rel="noopener noreferrer">开始播放</a>。

    app->system_state = 2;   /* playing */

### 开始音频传输

注册「开始音频传输」回调。飞机开始传输音频文件时下发该命令，携带文件类型、uuid、文件名与解码码率。负载在回调中创建临时文件并进入传输态。对应的 MQTT 协议见 <a href="../api-reference/api-speaker.html#开始音频传输" target="_blank" rel="noopener noreferrer">开始音频传输</a>。

```c
static T_ThingModelReturnCode on_trans_start(SpeakerImpl_t *impl, void *user,
        const T_SpeakerTransStartRequest *req, T_ThingModelCommonReply *reply)
{
    AppSpeaker *app = user;
    /* 按 uuid 建临时文件，记录 file_name 与 uuid，进入传输态 */
    if (open_transfer_file(app, req->uuid, req->file_name) != 0) {
        reply->result = -1;
        snprintf(reply->result_message, sizeof(reply->result_message), "failed to create file");
        return THING_MODEL_RC_OK;
    }
    app->system_state = 1;   /* transmitting */
    reply->result = 0;
    snprintf(reply->result_message, sizeof(reply->result_message), "success");
    return THING_MODEL_RC_OK;
}

SpeakerImpl_OnTransStart(spimpl, on_trans_start, &sp);
```

请求结构 `T_SpeakerTransStartRequest` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| file_type | int32_t | 文件类型。<ul><li>0：tts_txt</li><li>1：opus</li><li>2：wav</li></ul> |
| uuid | char * | 本次传输的唯一标识 |
| file_name | char * | 原始文件名 |
| decode_bitrate | int32_t | 解码码率。<ul><li>8000</li><li>16000</li><li>24000</li><li>32000</li><li>48000</li><li>64000</li></ul> |

### 传输音频数据包

注册「传输音频数据包」回调。飞机逐包下发音频二进制数据，负载按 `offset` 将数据写入临时文件。对应的 MQTT 协议见 <a href="../api-reference/api-speaker.html#传输音频数据包" target="_blank" rel="noopener noreferrer">传输音频数据包</a>。

```c
static T_ThingModelReturnCode on_trans_data(SpeakerImpl_t *impl, void *user,
        const T_SpeakerTransDataRequest *req, T_ThingModelCommonReply *reply)
{
    AppSpeaker *app = user;
    /* req->data 已由 SDK 从 hex 解为二进制（T_ThingModelBytes） */
    if (req->data.data && req->data.len > 0) {
        fseek(app->xfer.fp, req->offset, SEEK_SET);
        fwrite(req->data.data, 1, req->data.len, app->xfer.fp);
    }
    reply->result = 0;
    snprintf(reply->result_message, sizeof(reply->result_message), "success");
    return THING_MODEL_RC_OK;
}

SpeakerImpl_OnTransData(spimpl, on_trans_data, &sp);
```

:::warning 注意：
`T_SpeakerTransDataRequest` 的 `data` 字段类型为 `T_ThingModelBytes`（含 `data` 指针与 `len` 长度），SDK 已从 hex 字符串解码为二进制，回调中可按 `offset` 写入，无需再做 hex 解码。
:::

请求结构 `T_SpeakerTransDataRequest` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| packet_index | int32_t | 包序号 |
| offset | int32_t | 本包在文件中的字节偏移 |
| data | T_ThingModelBytes | 本包音频二进制数据（含 data 指针与 len 长度） |

### 结束音频传输

注册「结束音频传输」回调。飞机传输完成后下发该命令，携带整文件 MD5。负载在回调中计算文件 MD5 并与请求值比对，一致则保存为正式文件，否则通知对端重传。对应的 MQTT 协议见 <a href="../api-reference/api-speaker.html#结束音频传输" target="_blank" rel="noopener noreferrer">结束音频传输</a>。

```c
static T_ThingModelReturnCode on_trans_finish(SpeakerImpl_t *impl, void *user,
        const T_SpeakerTransFinishRequest *req, T_ThingModelCommonReply *reply)
{
    AppSpeaker *app = user;
    char got[33] = "";
    close_and_md5(app, got);   /* 关闭文件并计算 MD5 */

    if (req->md5 && strcasecmp(got, req->md5) != 0) {
        reply->result = -1;
        snprintf(reply->result_message, sizeof(reply->result_message), "md5 mismatch");
        return THING_MODEL_RC_OK;   /* 返回失败通知对端重传 */
    }
    commit_transfer_file(app);      /* 校验通过，重命名为正式文件 */
    app->system_state = 0;          /* idle */
    reply->result = 0;
    snprintf(reply->result_message, sizeof(reply->result_message), "success");
    return THING_MODEL_RC_OK;
}

SpeakerImpl_OnTransFinish(spimpl, on_trans_finish, &sp);
```

请求结构 `T_SpeakerTransFinishRequest` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| md5 | char * | 整文件 MD5（32 字符 hex），用于校验传输完整性 |

### 推送喊话器状态

通过推送端主动向飞机上报喊话器当前状态。构造状态结构后调用推送接口。对应的 MQTT 协议见 <a href="../api-reference/api-speaker.html#喊话器状态推送" target="_blank" rel="noopener noreferrer">喊话器状态推送</a>。

```c
T_SpeakerStatePush push = {
    .system_state   = 2,       /* playing */
    .work_mode      = 1,       /* voice */
    .play_mode      = 0,       /* single */
    .play_volume    = 50,
    .play_file_name = (char *)"alarm.opus",
    .play_file_uuid = (char *)"1a2b3c4d",
};
Speaker_PublishState(sppub, &push);
```

推送结构 `T_SpeakerStatePush` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| system_state | int32_t | 系统状态。<ul><li>0：idle</li><li>1：transmitting</li><li>2：playing</li><li>3：error</li><li>4：tts_conversion</li></ul> |
| work_mode | int32_t | 工作模式。<ul><li>0：TTS</li><li>1：voice</li></ul> |
| play_mode | int32_t | 播放模式。<ul><li>0：single</li><li>1：loop</li></ul> |
| play_volume | int32_t | 当前音量，0~100 |
| play_file_name | char * | 当前播放文件名 |
| play_file_uuid | char * | 当前播放文件 uuid |

### 销毁响应端与推送端

不再使用喊话器功能时，销毁响应端与推送端以释放资源。

```c
Speaker_DestroyPublisher(sppub);
SpeakerImpl_Destroy(spimpl);
```
