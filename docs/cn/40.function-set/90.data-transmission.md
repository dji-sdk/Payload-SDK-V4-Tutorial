## 概述

数据传输用于在负载与云端之间、负载之间透传自定义小数据。数据经飞机路由转发，单条最大 256 字节，适用于小体量遥测上报、负载间通信等场景。

负载通过发送端向目标设备发送数据，通过客户端注册回调接收其他设备经飞机转发的数据。收发均走 event 通道，不经请求 / 响应。

:::tip 说明：
- PSDK 中的 C 接口是对底层 MQTT 协议的封装，开发者通过调用 C 接口即可完成协议交互，无需手动构造 MQTT 报文。底层 MQTT 协议的 payload 结构与字段定义详见 <a href="../api-reference/api-data-transmission.html" target="_blank" rel="noopener noreferrer">协议参考-数据传输</a>。
- 使用本功能前，负载设备需先完成接入与鉴权，详见 <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">接入与鉴权</a>。
:::

## 基础概念

### 名词解释

**通道地址 (channel address)**

标识数据收发的设备端点。发送时用于指定目标设备，接收时表示数据来源设备。取值涵盖负载 1/2/3 与云端。

**发送端 (publisher)**

负载侧用于主动向目标设备发送数据的对象。数据经飞机路由至目标设备。

**客户端 (client)**

负载侧用于接收其他设备发来数据的对象。负载注册处理回调，其他设备经飞机转发的数据由 SDK 回调到负载。

### 通道地址取值

发送数据的目标地址与接收数据的来源地址均使用通道地址枚举 `E_ChannelAddress`，取值如下：

| 枚举常量 | 数值 | 含义 |
|------|------|------|
| CHANNEL_ADDRESS_PAYLOAD_NO1 | 1 | 负载 1 号位 |
| CHANNEL_ADDRESS_PAYLOAD_NO2 | 2 | 负载 2 号位 |
| CHANNEL_ADDRESS_PAYLOAD_NO3 | 3 | 负载 3 号位 |
| CHANNEL_ADDRESS_CLOUD | 15 | 云端 |

:::warning 注意：
单条透传数据的 `payload` 最大 256 字节，超出可能被截断或丢弃。接收回调在后台线程触发，回调内不应调用同步 API，也不应销毁客户端或发送端；耗时逻辑应转交其他线程处理。若在接收回调中向来源设备回发数据，须避免收发双方相互应答形成无限循环。
:::

## 功能介绍

:::warning 注意：
以下代码为参考示例，用于说明各功能的调用流程与实现方式。开发者可结合负载设备的硬件特性和应用场景进行适配。
:::

### 创建客户端与发送端

在已建立的 MQTT 会话 `session` 上创建数据传输客户端与发送端。接收数据通过客户端注册回调，发送数据通过发送端发出。

```c
CustomSmallData_Client_t    *client    = CustomSmallData_CreateClient(session);
CustomSmallData_Publisher_t *publisher = CustomSmallData_CreatePublisher(session);
```

### 接收数据

注册回调以接收其他设备经飞机转发的数据。回调在收到数据时被触发，参数 `push` 指向解码后的接收数据结构体，其中 `source` 为来源设备地址，`payload` 为透传数据。对应的 MQTT 协议见 <a href="../api-reference/api-data-transmission.html#接收数据" target="_blank" rel="noopener noreferrer">接收数据</a>。

```c
static void on_transmit_push(void *user, const T_TransmitEventPush *push)
{
    if (!push) return;
    USER_LOG_INFO("recv from %d, len=%u, data=%.*s",
                  push->source, (unsigned)push->payload.len,
                  (int)push->payload.len, (const char *)push->payload.data);
}

T_ThingModelReturnCode rc = CustomSmallData_OnTransmitPush(client, on_transmit_push, NULL);
if (rc != THING_MODEL_RC_OK) {
    USER_LOG_ERROR("register transmit push callback failed: rc=%d", rc);
}
```

接收结构 `T_TransmitEventPush` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| source | E_ChannelAddress | 数据来源，即该透传数据的发出设备。<ul><li>CHANNEL_ADDRESS_PAYLOAD_NO1：负载 1 号位</li><li>CHANNEL_ADDRESS_PAYLOAD_NO2：负载 2 号位</li><li>CHANNEL_ADDRESS_PAYLOAD_NO3：负载 3 号位</li><li>CHANNEL_ADDRESS_CLOUD：云端</li></ul> |
| payload.data | uint8_t * | 透传数据缓冲区指针 |
| payload.len | size_t | 透传数据字节数，最大 256 |

:::warning 注意：
回调在后台线程触发，回调内不应调用同步 API，也不应销毁客户端或发送端。`push->payload.data` 指向的缓冲区仅在回调期间有效，如需保留数据应在回调内拷贝。
:::

### 发送数据

向指定目标设备发送一条小数据。调用前先用 `CustomSmallData_InitTransmitRequest()` 初始化请求结构体，再设置目标地址 `target` 与透传数据 `payload`。对应的 MQTT 协议见 <a href="../api-reference/api-data-transmission.html#发送数据" target="_blank" rel="noopener noreferrer">发送数据</a>。

```c
const char *msg = "hello cloud";

T_TransmitRequest req;
CustomSmallData_InitTransmitRequest(&req);
req.target       = CHANNEL_ADDRESS_CLOUD;
req.payload.data = (uint8_t *)msg;
req.payload.len  = strlen(msg) + 1;

T_ThingModelReturnCode rc = CustomSmallData_PublishTransmit(publisher, &req);
if (rc != THING_MODEL_RC_OK) {
    USER_LOG_ERROR("transmit failed: rc=%d", rc);
}
```

请求结构 `T_TransmitRequest` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| target | E_ChannelAddress | 目标设备通道地址，取值见 [通道地址取值](#通道地址取值) |
| payload.data | uint8_t * | 待发送数据缓冲区指针 |
| payload.len | size_t | 待发送数据字节数，最大 256 |

:::tip 说明：
本接口为 event 发送，采用 fire-and-forget 语义，无飞机应答；返回码 `rc` 仅表示本地发送是否成功提交，不代表目标设备已收到。
:::

### 销毁客户端与发送端

不再使用数据传输功能时，销毁客户端与发送端以释放资源。应先断开会话再销毁客户端与发送端，避免在途消息回调访问已释放对象。

```c
CustomSmallData_DestroyPublisher(publisher);
CustomSmallData_DestroyClient(client);
```
