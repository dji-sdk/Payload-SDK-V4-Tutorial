## 概述

:::warning 注意：
MOP 数据通道的数据面基于 POSIX TCP socket，仅支持 Linux 平台，不适用于 RTOS 构建。使用前须确认负载运行环境为 Linux，且飞机固件已支持 MOP 通道。
:::

SDK 互联互通用于在负载设备与移动端 MSDK、机载 OSDK 或其他负载 PSDK 设备之间建立通信链路。其中 MOP 是其数据通道功能，用于创建高速通道、传输大体量业务数据。

MOP 数据通道采用控制面和数据面分离的架构：控制面通过 MQTT 协商目标设备、通道参数和状态；数据面由负载根据返回的 ip / port 自行建立 TCP 连接，不经 MQTT。

:::tip 说明：
- PSDK 中的 C 接口是对底层 MQTT 协议的封装，开发者通过调用 C 接口即可完成协议交互，无需手动构造 MQTT 报文。底层 MQTT 协议的 payload 结构与字段定义详见 <a href="../api-reference/api-sdk-interconnection.html" target="_blank" rel="noopener noreferrer">协议参考-SDK 互联互通</a>。
- 使用本功能前，负载设备需先完成接入与鉴权，详见 <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">接入与鉴权</a>。
:::

## 基础概念

### 名词解释

**控制面 (control plane)**

经 MQTT 协议协商通道参数与状态的通道，承载启用 / 关闭通道命令与通道状态推送。

**数据面 (data plane)**

承载实际业务数据的 TCP 通道。负载依据控制面返回的 ip / port 自行建立 TCP 连接并收发数据，数据不经 MQTT。

**通道角色 (role)**

通道两端的连接角色。`ROLE_SERVER` 监听等待对端连接，`ROLE_CLIENT` 主动连接对端。

**传输类型 (reliability)**

数据面的传输类型。`RELIABILITY_RELIABLE` 为可靠传输，`RELIABILITY_UNRELIABLE` 为非可靠传输。

### 通道建立时序

完整的通道生命周期由负载驱动控制面、自行管理数据面，时序如下：

1. **启用通道**：负载调用 `MopChannel_Enable()`，飞机在响应中返回通道状态 `state`、TCP 数据面端点 `ip` / `port`。
2. **建立数据面**：负载依据 `ip` / `port` 建立 TCP 连接。
3. **等待就绪**：飞机通过通道状态推送下发 `CHANNEL_STATE_ACTIVE`，表示数据面就绪，负载可开始 TCP 收发。
4. **关闭通道**：负载调用 `MopChannel_Disable()`，飞机应答后通过通道状态推送下发 `CHANNEL_STATE_CLOSED`，负载据此安全关闭 TCP socket。

:::warning 注意：
- 通道 ID 不限制固定取值范围，两端约定使用同一个通道号即可建立通信。
- 负载应先注册通道状态回调 `MopChannel_OnChannelEvent()`，再调用 `MopChannel_Enable()`，避免漏收 ACTIVE 状态。
- 收到 `CHANNEL_STATE_CLOSED` 后应安全关闭 TCP socket；若在等待 ACTIVE 期间收到 CLOSED，通常表示对端设备未就绪。
- 通道状态回调在后台线程触发，回调内不应调用同步 API（如 `MopChannel_Enable()` / `MopChannel_Disable()`），也不应销毁客户端；TCP 收发应在独立线程中进行。
:::

## 功能介绍

:::warning 注意：
以下代码为参考示例，用于说明各功能的调用流程与实现方式。开发者可结合负载设备的硬件特性和应用场景进行适配。
:::

### 创建客户端

在已建立的 MQTT 会话 `session` 上创建 MOP 通道客户端，后续接口均通过该客户端调用。

```c
MopChannel_Client_t *client = MopChannel_CreateClient(session);
```

### 接收通道状态

注册回调以接收飞机推送的通道状态。回调在通道状态变化时被触发，参数 `push` 指向解码后的状态推送结构体。应先注册回调，再启用通道，避免漏收 ACTIVE 状态。对应的 MQTT 协议见 <a href="../api-reference/api-sdk-interconnection.html#通道状态推送" target="_blank" rel="noopener noreferrer">通道状态推送</a>。

```c
static void on_channel_event(void *user, const T_ChannelEventPush *push)
{
    if (!push) return;
    if (push->state == CHANNEL_STATE_ACTIVE) {
        /* 数据面就绪，通知收发线程开始 TCP 读写 */
    } else if (push->state == CHANNEL_STATE_CLOSED) {
        /* 通道关闭，安全关闭 TCP socket */
    }
}

T_ThingModelReturnCode rc = MopChannel_OnChannelEvent(client, on_channel_event, NULL);
if (rc != THING_MODEL_RC_OK) {
    USER_LOG_ERROR("register channel event callback failed: rc=%d", rc);
}
```

推送结构 `T_ChannelEventPush` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| channel_id | uint32_t | 通道 ID，两端约定使用同一个通道号即可建立通信 |
| state | E_ChannelState | 通道状态。<ul><li>CHANNEL_STATE_ACTIVE（1）：数据面就绪</li><li>CHANNEL_STATE_CLOSED（2）：通道关闭，应安全关闭 socket</li></ul> |

:::warning 注意：
回调在后台线程触发，回调内不应调用同步 API 或销毁客户端；TCP 收发与耗时逻辑应转交其他线程处理。
:::

### 启用通道

启用数据通道，飞机在响应中返回 TCP 数据面端点。调用前先用 `MopChannel_InitMopEnableRequest()` 初始化请求结构体，设置角色、传输类型、通道 ID、目标设备类型与目标地址。对应的 MQTT 协议见 <a href="../api-reference/api-sdk-interconnection.html#启用通道" target="_blank" rel="noopener noreferrer">启用通道</a>。

```c
T_MopEnableRequest req;
MopChannel_InitMopEnableRequest(&req);
req.role               = ROLE_CLIENT;
req.reliability        = RELIABILITY_RELIABLE;
req.channel_id         = 49153;
req.target_device_type = TARGET_DEVICE_TYPE_PSDK;
req.target_address     = 1;   /* client 模式下为目标负载位置 1/2/3 */

T_MopEnableReply reply;
MopChannel_InitMopEnableReply(&reply);
T_ThingModelReturnCode rc = MopChannel_Enable(client, &req, &reply, 5000);
if (rc == THING_MODEL_RC_OK && reply.result == 0) {
    USER_LOG_INFO("enable ok: state=%s ip=%s port=%u",
                  reply.state, reply.ip, reply.port);
    /* 依据 reply.ip / reply.port 建立 TCP 连接 */
} else {
    USER_LOG_ERROR("enable failed: rc=%d result=%d msg=%s",
                   rc, reply.result, reply.result_message);
}
MopChannel_FreeMopEnableReply(&reply);
```

请求结构 `T_MopEnableRequest` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| role | E_Role | 通道角色。<ul><li>ROLE_SERVER（0）：监听等待对端连接</li><li>ROLE_CLIENT（1）：主动连接对端</li></ul> |
| reliability | E_Reliability | 传输类型。<ul><li>RELIABILITY_RELIABLE（0）：可靠传输</li><li>RELIABILITY_UNRELIABLE（1）：非可靠传输</li></ul> |
| channel_id | uint32_t | 通道 ID，两端约定使用同一个通道号即可建立通信 |
| target_device_type | E_TargetDeviceType | 目标设备 SDK 类型。<ul><li>TARGET_DEVICE_TYPE_MSDK（1）：移动端</li><li>TARGET_DEVICE_TYPE_OSDK（2）：机载</li><li>TARGET_DEVICE_TYPE_PSDK（3）：负载</li></ul> |
| target_address | uint32_t | 目标地址。<ul><li>client 模式：目标负载位置 1、2、3</li><li>server 模式：固定为 0</li></ul> |

应答结构 `T_MopEnableReply` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| result | int32_t | 处理结果，0 表示成功 |
| result_message | char * | 结果描述信息 |
| channel_id | uint32_t | 通道 ID |
| state | char * | 通道状态，成功时为 "listening" |
| ip | char * | TCP 数据面端点 IP 地址 |
| port | uint32_t | TCP 数据面端点端口 |

:::tip 说明：
`T_MopEnableReply` 含 `char *` 字段，用完后须调用 `MopChannel_FreeMopEnableReply()` 释放。启用成功后应先依据 `ip` / `port` 建立 TCP 连接，再等待通道状态推送 `CHANNEL_STATE_ACTIVE` 确认数据面就绪。
:::

### 关闭通道

关闭数据通道。飞机应答后通过通道状态推送下发 `CHANNEL_STATE_CLOSED`，负载据此安全关闭 TCP socket。对应的 MQTT 协议见 <a href="../api-reference/api-sdk-interconnection.html#关闭通道" target="_blank" rel="noopener noreferrer">关闭通道</a>。

```c
T_MopDisableRequest req;
MopChannel_InitMopDisableRequest(&req);
req.channel_id = 49153;

T_Placeholder resp;
memset(&resp, 0, sizeof(resp));
T_ThingModelReturnCode rc = MopChannel_Disable(client, &req, &resp, 5000);
if (rc != THING_MODEL_RC_OK) {
    USER_LOG_ERROR("disable failed: rc=%d", rc);
}
/* 等待通道状态推送 CHANNEL_STATE_CLOSED 后关闭 TCP socket */
```

请求结构 `T_MopDisableRequest` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| channel_id | uint32_t | 待关闭的通道 ID |

:::tip 说明：
关闭通道的 service 响应为空，真正的关闭信号由通道状态推送 `CHANNEL_STATE_CLOSED` 下发。负载应在收到 CLOSED 后再关闭 TCP socket，避免数据面残留。
:::

### 销毁客户端

不再使用 MOP 通道功能时，销毁客户端以释放资源。销毁前应先关闭已启用的通道并断开会话。

```c
MopChannel_DestroyClient(client);
```
