## 概述

安全接入（Secure Access）是所有业务功能的前置步骤。负载设备作为 MQTT 客户端接入飞机端 broker 后，方可在会话上创建各能力 client 并收发业务报文。

:::tip 说明：
PSDK 中的 C 接口是对底层 MQTT 协议的封装，开发者通过调用 C 接口即可完成协议交互，无需手动构造 MQTT 报文。底层 MQTT 协议的连接参数、鉴权报文构造规则与字段定义详见 <a href="../api-reference/api-access-authentication.html" target="_blank" rel="noopener noreferrer">协议参考-接入与鉴权</a>。
:::

## 接口总览

安全接入通过 `ThingModelClientSession_Connect()` 完成。调用该接口时，需传入一份接入配置 `ThingModelClientSession_Config_t`。接口调用成功后返回会话句柄，可在该会话上创建能力 client 并收发各业务 Topic 的报文。退出前需调用 `ThingModelClientSession_Disconnect()` 释放会话。

## 接入参数

接入参数即接入配置 `ThingModelClientSession_Config_t` 的字段。其中 `app_id`、`app_name`、`app_key`、`app_license` 为应用凭据，获取方式详见 <a href="../payload-quick-start/quick-demo/raspberry-pi.html#获取应用信息" target="_blank" rel="noopener noreferrer">获取应用信息</a>；其余为设备与连接信息。

| 字段 | 类型 | 必填 | 含义与填写方式 |
|:---|:---|:---|:---|
| app_id | string | 是 | 应用 ID，填写平台分配的字符串。 |
| app_name | string | 否 | 应用名称，即创建应用时填写的名称（如 `psdkappfortest`）。服务器据此识别应用身份，建议填写。 |
| app_key | string | 是 | 应用密钥，请妥善保管，勿硬编码进版本库。 |
| app_license | string | 是 | 应用授权码。 |
| device_sn | string | 是 | 负载设备序列号，由负载开发者自定义（**非飞机 SN**），用于标识接入的负载，其同时作为 MQTT 连接标识及各业务 Topic 中的 `{client_id}`。<br>格式要求：由数字、字母、下划线（`_`）组成，长度不超过 64 个字符；每个负载客户端需使用各自不同的 `device_sn`。 |
| broker_address | string | 是 | 飞机端 broker 的地址。按飞机型号填写，例如 Matrice 5TD 为 `192.168.100.3`。 |
| broker_port_tls | int | 是 | TLS 鉴权连接端口，填写 `8883`。 |
| broker_port | int | 是 | 业务长连接端口，填写 `1883`。 |
| ca_cert_path | string | 是 | CA 证书（`ca.crt`）路径，用于校验 broker 的服务器证书。证书获取方式详见 <a href="../payload-quick-start/quick-demo/raspberry-pi.html#下载证书" target="_blank" rel="noopener noreferrer">下载证书</a>。 |

## 调用示例

以下示例展示如何填写接入配置，并完成会话建立与释放。

```c
#include "thing_model_client/thing_model_client_session.h"

ThingModelClientSession_Config_t cfg = {0};
cfg.app_id          = "your_app_id";
cfg.app_name        = "your_app_name";
cfg.app_key         = "your_app_key";
cfg.app_license     = "your_app_license";
cfg.device_sn       = "your_device_sn";
cfg.broker_address  = "192.168.100.3";     /* 飞机端 MQTT 服务器地址，按飞机型号填写 */
cfg.broker_port_tls = 8883;
cfg.broker_port     = 1883;
cfg.ca_cert_path    = "/path/to/ca.crt";

ThingModelClientSession_t *s = ThingModelClientSession_Connect(&cfg);
if (!s) {
    /* 接入失败，通过 ThingModelClientSession_GetLastError() 查询原因 */
    return;
}

/* ... 基于该会话创建能力 client 并收发业务报文 ... */

ThingModelClientSession_Disconnect(s);
```

SDK 示例（如 `samples/` 目录下的 EFTS）已将接入流程封装为 `sample_session_open(&cfg)`，该函数内部同样调用 `ThingModelClientSession_Connect()`。

## 鉴权说明

接入过程包含两次鉴权，均由 SDK 在 `ThingModelClientSession_Connect()` 内部自动完成，业务代码无需参与具体鉴权流程：

1. **基于应用凭据的鉴权**：通过 TLS 连接 broker 的 `8883` 端口，在加密通道内以应用凭据完成鉴权。鉴权通过后，导出与本次连接绑定的密钥材料，随后断开该连接。
2. **基于 token 的鉴权**：使用上一步导出的密钥材料计算 token，通过普通 MQTT 连接 broker 的 `1883` 端口，建立业务长连接。后续所有业务报文均复用此连接。

:::warning 注意：
- TLS 仅用于加密传输通道并校验 broker 的服务器证书，不直接用于负载身份鉴权。负载身份鉴权由上述两次鉴权流程完成。

- 若接入失败并返回鉴权错误，请检查应用凭据（App Key / App License）、设备序列号与 CA 证书是否正确。
:::

接入过程涉及的报文构造规则与字段定义详见 <a href="../api-reference/api-access-authentication.html" target="_blank" rel="noopener noreferrer">协议参考-接入与鉴权</a>。
