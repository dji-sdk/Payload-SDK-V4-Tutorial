## 概述

本地升级（Upgrade）用于由飞机在线升级负载固件。升级流程由飞机发起：飞机依次下发进入升级模式、校验固件、启动升级、完成升级 4 个命令，负载作为响应方处理。

固件文件通过负载侧 HTTP 服务传输，不走 MQTT。升级执行期间，负载通过 MQTT 持续上报升级进度和结果。

:::tip 说明：
- PSDK 中的 C 接口是对底层 MQTT 协议的封装，开发者通过调用 C 接口即可完成协议交互，无需手动构造 MQTT 报文。底层 MQTT 协议的 payload 结构与字段定义详见 <a href="../api-reference/api-local-update.html" target="_blank" rel="noopener noreferrer">协议参考-本地升级</a>。
- 使用本功能前，负载设备需先完成接入与鉴权，详见 <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">接入与鉴权</a>。
:::

## 基础概念

### 名词解释

**升级命令响应端 (impl)**

负载侧用于接收并响应飞机下发的 4 个升级命令的对象。负载为每个命令注册一个处理回调，飞机下发对应命令时由 SDK 回调到负载。

**升级状态推送端 (publisher)**

负载侧用于主动向飞机上报升级状态的对象。升级执行期间，负载通过该对象周期推送当前升级阶段、进度和最终结果。

### 升级时序

完整升级流程由飞机驱动，负载按以下时序响应：

1. **进入升级模式**：飞机下发 `enter_upgrade_mode`，负载返回等待秒数 `wait_time` 与固件下载地址 `url`。
2. **校验固件**：飞机经 `url` 下载或上传固件后下发 `check_firmware`，负载校验固件并返回结果。
3. **启动升级**：飞机下发 `start_upgrade`，负载立即应答，随后在后台执行升级，并通过推送端上报升级进度和结果：升级中（进度 0~100）→ 重启中（重启超时秒数）→ 升级完成（成功 / 失败）。其中升级中与完成阶段以 1 Hz 推送。
4. **完成升级**：飞机下发 `finish_upgrade`，负载停止状态推送并应答。

:::warning 注意：
- 负载收到 `start_upgrade` 后应先返回应答，再启动后台升级，避免阻塞命令响应。
- 升级一旦开始，负载进程应保持运行直至收到 `finish_upgrade`；升级中途退出会导致升级失败。
- 若负载在升级过程中真实重启，重启前应将升级结果持久化，重启后据此继续推送升级完成状态，直至收到 `finish_upgrade`。
:::

## 功能介绍

:::warning 注意：
以下代码为参考示例，用于说明各功能的调用流程与实现方式。开发者可结合负载设备的硬件特性和应用场景进行适配。
:::

### 创建响应端与推送端

在已建立的 MQTT 会话 `s` 上创建升级命令响应端与状态推送端，后续命令回调通过响应端注册，状态推送通过推送端发出。

```c
UpgradeImpl_t *impl = UpgradeImpl_Create(s, device_sn);
Upgrade_Publisher_t *pub = Upgrade_CreatePublisher(s);
```

### 进入升级模式

注册「进入升级模式」回调。飞机下发该命令时，负载在回调中返回飞机需等待的秒数 `wait_time` 与固件下载地址 `url`。对应的 MQTT 协议见 <a href="../api-reference/api-local-update.html#进入升级模式" target="_blank" rel="noopener noreferrer">进入升级模式</a>。

```c
static T_ThingModelReturnCode on_enter_mode(UpgradeImpl_t *impl, void *user,
                                            const T_Placeholder *req,
                                            T_UpgradeEnterModeReply *reply)
{
    reply->result         = 0;
    reply->result_message = strdup("ok");
    reply->wait_time      = 10;
    reply->url            = strdup("http://192.168.1.10:8000/upgrade.bin");
    return THING_MODEL_RC_OK;
}

UpgradeImpl_OnEnterUpgradeMode(impl, on_enter_mode, NULL);
```

:::tip 说明：
`T_UpgradeEnterModeReply` 的 `result_message` 与 `url` 为 `char *`，SDK 回包后会释放，须用 `strdup` 等方式堆分配，不能使用字符串字面量或栈地址。
:::

应答结构 `T_UpgradeEnterModeReply` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| result | int32_t | 处理结果，0 表示成功 |
| result_message | char * | 结果描述信息 |
| wait_time | int32_t | 飞机应等待的秒数，用于负载准备存储区等前置操作 |
| url | char * | 固件下载地址，飞机通过 HTTP 从该地址获取固件 |

### 校验固件

注册「校验固件」回调。飞机获取固件后下发该命令，负载在回调中校验固件并返回结果，校验失败时将 `result` 置为非 0。对应的 MQTT 协议见 <a href="../api-reference/api-local-update.html#校验固件" target="_blank" rel="noopener noreferrer">校验固件</a>。

```c
static T_ThingModelReturnCode on_check_firmware(UpgradeImpl_t *impl, void *user,
                                                const T_Placeholder *req,
                                                T_ThingModelCommonReply *reply)
{
    int ok = firmware_check();   /* 校验签名 / 解密 / 完整性 / 版本，返回是否通过 */
    reply->result = ok ? 0 : -1;
    snprintf(reply->result_message, sizeof(reply->result_message),
             ok ? "firmware check ok" : "firmware invalid");
    return THING_MODEL_RC_OK;
}

UpgradeImpl_OnCheckFirmware(impl, on_check_firmware, NULL);
```

:::tip 说明：
`T_ThingModelCommonReply` 的 `result_message` 为定长字符数组，应使用 `snprintf` 填写，不应使用 `strdup`。
:::

### 启动升级

注册「启动升级」回调。负载在回调中立即应答，再启动后台线程执行升级并推送升级进度和结果，避免在回调中长时间阻塞。对应的 MQTT 协议见 <a href="../api-reference/api-local-update.html#启动升级" target="_blank" rel="noopener noreferrer">启动升级</a>。

```c
static T_ThingModelReturnCode on_start_upgrade(UpgradeImpl_t *impl, void *user,
                                               const T_Placeholder *req,
                                               T_ThingModelCommonReply *reply)
{
    reply->result = 0;
    snprintf(reply->result_message, sizeof(reply->result_message), "ok");
    start_upgrade_thread();   /* 后台执行升级并通过 publisher 推送状态 */
    return THING_MODEL_RC_OK;
}

UpgradeImpl_OnStartUpgrade(impl, on_start_upgrade, NULL);
```

### 完成升级

注册「完成升级」回调。负载在回调中停止状态推送并应答。对应的 MQTT 协议见 <a href="../api-reference/api-local-update.html#完成升级" target="_blank" rel="noopener noreferrer">完成升级</a>。

```c
static T_ThingModelReturnCode on_finish_upgrade(UpgradeImpl_t *impl, void *user,
                                                const T_Placeholder *req,
                                                T_ThingModelCommonReply *reply)
{
    stop_upgrade_thread();     /* 停止后台升级与状态推送 */
    reply->result = 0;
    snprintf(reply->result_message, sizeof(reply->result_message), "ok");
    return THING_MODEL_RC_OK;
}

UpgradeImpl_OnFinishUpgrade(impl, on_finish_upgrade, NULL);
```

### 推送升级状态

升级执行期间，负载通过推送端主动向飞机上报升级状态，阶段依次为：升级中 → 重启中（若涉及重启）→ 升级完成。`value` 字段含义随 `upgrade_stage` 变化。对应的 MQTT 协议见 <a href="../api-reference/api-local-update.html#升级状态推送" target="_blank" rel="noopener noreferrer">升级状态推送</a>。

```c
T_UpgradeStatePush p = { .upgrade_stage = UPGRADE_STAGE_UPGRADING, .value = 50 };
Upgrade_PublishPushUpgradeState(pub, &p);
```

推送结构 `T_UpgradeStatePush` 的字段说明：

| 字段 | 类型 | 说明 |
|------|------|------|
| upgrade_stage | E_UpgradeStage | 升级阶段。<ul><li>UPGRADE_STAGE_IDLE（0）：空闲</li><li>UPGRADE_STAGE_UPGRADING（3）：升级中</li><li>UPGRADE_STAGE_COMPLETE（4）：升级完成</li><li>UPGRADE_STAGE_REBOOTING（6）：设备重启中</li></ul> |
| value | int32_t | 含义随阶段变化。<ul><li>升级中：进度 0~100</li><li>升级完成：结果，1 为成功，2 为失败</li><li>设备重启中：重启超时秒数 0~255</li></ul> |

### 销毁响应端与推送端

升级流程结束后，销毁响应端与推送端以释放资源。

```c
UpgradeImpl_Destroy(impl);
Upgrade_DestroyPublisher(pub);
```
