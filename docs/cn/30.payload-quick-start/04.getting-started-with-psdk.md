本文档适用于基于 DJI Payload SDK（MQTT）的负载开发者，聚焦讲解**在 SDK 侧如何编写代码调用负载能力**：引入 SDK、配置接入信息、建立会话、创建能力 client、发起各类调用，并最终集成进自有工程。

:::tip 说明：
本章仅介绍 SDK 代码调用方式，与具体硬件平台无关。如需在真机上运行完整 Demo（涉及硬件连接、创建应用、下载证书、编译、应用绑定与运行），请先根据所用硬件阅读 <a href="./quick-demo/raspberry-pi.html" target="_blank" rel="noopener noreferrer">树莓派（Linux）快速体验</a> 或 <a href="./quick-demo/E-Port-V3.html" target="_blank" rel="noopener noreferrer">E‑Port V3（RTOS）快速体验</a>。

## 总体流程

Payload SDK 提供 C 客户端代码，负载设备作为 MQTT client 接入飞机端 broker，与飞行平台进行通信。在 SDK 侧编写代码调用负载能力，主要包含以下四个步骤：

1. **配置接入信息**：App ID / App Key / App License / Device SN / broker 地址 / CA 证书。
2. **建立会话（Session）**：完成两阶段鉴权，获得一个可复用的 `ThingModelClientSession_t`。
3. **创建能力 Client**：为每个业务能力（data_subscription、widget、power 等）创建对应的 cap client。
4. **发起调用**：通过 client 调用 SERVICE / PROPERTY，或订阅 EVENT / OSD 推送。

下文以 Linux 平台 C 语言为例，从 SDK 目录结构入手，逐步说明最小完整流程。

## SDK 包目录结构

发布包是**自包含**的：协议代码与 C 运行时源码均已随包提供，无需额外安装其他工具即可编译。与本章相关的目录如下（以下目录仅供参考，实际的目录以实际发布的版本包为准）：

```
payload-sdk-iot/
├── sdk/
│   ├── generated/c/     协议代码，按能力域分目录（data_subscription / widget / power / efts / …）
│   └── runtime/c/       最小 C 运行时（会话 + 鉴权 + 传输；host 与 rtos 两套后端）
│       └── include/     运行时对外头文件（thing_model_client/*.h）
├── samples/
│   ├── launcher/        样例注册表、共享会话、设备信息上报
│   ├── <能力>/src/      各能力域的样例源码（如 data_subscription/src/…）
│   └── third_party/     cJSON、mongoose、预编译 OpenSSL / mosquitto
└── projects/
    ├── linux/           Linux host / aarch64 单可执行工程   ← 从这里构建
    └── rtos/gd32f527/   GD32F527 RTOS 工程
```

编写代码调用负载能力时，只需关注以下三处：

- `sdk/runtime/c/include/thing_model_client/`：会话与 OSAL 等运行时接口头文件。
- `sdk/generated/c/<cap>/`：各能力域的 client 头文件与实现。
- `samples/<cap>/src/`：官方样例，可作为编写自有代码时的参考。

## 引入 SDK

将 SDK 集成进 CMake 工程需完成三项工作：**引入运行时**、**引入协议代码**、**正确链接默认实现**。

### 引入头文件

编写代码前，需引用运行时会话头文件，以及所需能力域的 client 头文件。每个能力域对应 `sdk/generated/c/` 下的一个目录，例如 `data_subscription/` 对应数据订阅功能：

```c
#include "thing_model_client/thing_model_client_session.h"  /* 会话门面 */
#include "thing_model_client/thing_model_client_osal.h"      /* OSAL 注册 */
#include "data_subscription/data_subscription_client.h"      /* 能力 client */
#include "data_subscription/data_subscription_types.h"       /* 请求/应答结构体 */
#include "common/common_types.h"
```

### 引入运行时与协议代码

在 CMake 工程中引入运行时子工程，并将所需能力域的协议代码编入目标（target）：

```cmake
# 1) 选择平台（Linux 用 host，MCU 用 rtos）
set(THING_MODEL_PLATFORM host CACHE STRING "" FORCE)

# 2) 引入运行时
add_subdirectory(path/to/sdk/runtime/c _thing_model_runtime)

# 3) 将协议代码编入目标
file(GLOB_RECURSE TM_GEN_SOURCES path/to/sdk/generated/c/*.c)
add_executable(my_payload main.c ${TM_GEN_SOURCES})
target_include_directories(my_payload PRIVATE
    path/to/sdk/generated/c
    path/to/sdk/runtime/c/include)
```

### 正确链接默认实现

默认的 MQTT 传输（mosquitto）与加密（openssl）实现通过**弱符号工厂注册**，必须使用 `--whole-archive` 完整链接，否则运行时将因缺少实现而连接失败：

```cmake
target_link_libraries(my_payload PRIVATE
    -Wl,--whole-archive
    thing_model_client_transport_mosquitto
    thing_model_client_crypto_openssl
    -Wl,--no-whole-archive
    thing_model_client_runtime
    pthread)
```

:::warning 注意：
`--whole-archive` 不可省略。缺少该选项时，默认的 mosquitto 传输与 openssl 加密实现不会被链接器纳入。
:::

如需移植到自有协议栈、替换默认的传输或加密实现，可在会话配置中注入自定义 vtable，接口定义见 `sdk/runtime/c/include/thing_model_client/thing_model_client_transport.h` 与 `..._crypto.h`。

## 配置接入信息

建立会话需要一份接入凭据，包括 App ID、App Name、App Key、App License、Device SN、broker 地址与 CA 证书。这些信息来自 <a href="./quick-demo/raspberry-pi.html#创建应用" target="_blank" rel="noopener noreferrer">创建应用</a> 与 <a href="./quick-demo/raspberry-pi.html#下载证书" target="_blank" rel="noopener noreferrer">下载证书</a>，各字段的类型、是否必填及填写方式详见 <a href="./quick-demo/raspberry-pi.html#补充应用信息" target="_blank" rel="noopener noreferrer">补充应用信息</a>。

在样例工程中，上述值集中填写于 `projects/linux/sample_config_local.h`；运行时也可使用同名 `THING_MODEL_*` 环境变量覆盖（优先级：环境变量 > 本地头文件 > 源码占位符默认值）。请勿将真实的 App Key / App License 提交进版本库。

:::warning 注意：
CA 证书路径必须为**真实可读的绝对路径**，这是首次接入时最常见的问题。若仍为占位符 `/path/to/ca.crt`，TLS 握手将在加载信任链时直接失败。
:::

## 建立会话（Session）

`ThingModelClientSession_t` 是**会话门面**。所有 cap client 共享同一个 session，由其负责 topic 订阅、消息分发与重连。

### 两阶段鉴权

接入过程包含两次鉴权，由 `ThingModelClientSession_Connect()` 内部自动完成：

1. **基于应用凭据的鉴权（Phase1）**：通过 TLS 连接 broker 8883 端口，在加密通道上以应用凭据完成鉴权，导出 RFC 5705 keying material 作为 HMAC key，随后断开。
2. **基于 token 的鉴权（Phase2）**：使用 `HMAC-SHA256(key, SN)` 生成 token，连接 broker 1883 端口（普通 MQTT），后续 publish 报文在包尾附加 timestamp 与 HMAC 签名。

TLS 仅用于加密传输通道并校验 broker 的服务器证书，其本身不构成对负载身份的鉴权。**8883 与 1883 两个端口均需连通**；日志中会依次出现 `Phase1 ...` 与 `Phase2 connected, session ready`。

### 建立与释放

首先注册一个 OSAL（Linux 使用内置的 POSIX 实现），再填充配置并连接：

```c
/* 1. 注册 POSIX OSAL（Linux） */
ThingModelOsal_RegisterPosix();

/* 2. 填充会话配置 */
ThingModelClientSession_Config_t cfg = {
    .app_id          = "YOUR_APP_ID",
    .app_name        = "psdkappfortest",
    .app_key         = "YOUR_APP_KEY",
    .app_license     = "YOUR_APP_LICENSE",
    .device_sn       = "SN1234567890",
    .broker_address  = "192.168.100.3",
    .broker_port_tls = 8883,
    .broker_port     = 1883,
    .ca_cert_path    = "/绝对路径/ca.crt",
    .topic_style     = THING_MODEL_TOPIC_STYLE_V2,  /* 默认 V2 */
    .auto_reconnect  = true,                        /* 建议开启断线重连 */
    .reconnect_delay_min_sec = 1,
    .reconnect_delay_max_sec = 30,
};

/* 3. 连接（内部完成两阶段鉴权） */
ThingModelClientSession_t *s = ThingModelClientSession_Connect(&cfg);
if (!s) {
    const T_ThingModelLastError *e = ThingModelClientSession_GetLastError();
    fprintf(stderr, "connect failed: rc=%d %s\n", e->rc, e->message);
    return -1;
}

/* ... 创建 client、发起调用 ... */

ThingModelClientSession_Disconnect(s);
```

:::tip 说明：
连接失败时，除判断 `Connect()` 是否返回 NULL 外，建议调用 `ThingModelClientSession_GetLastError()` 获取 `rc` / `transport_rc` / `errno` 及文字描述，以便更准确地定位问题。
:::

## 创建能力 Client

每个业务能力对应一个 client 结构体，通过 `<Cap>_CreateClient(session)` 创建，通过 `<Cap>_DestroyClient()` 释放。所有 client 均基于同一个 session：

```c
Speaker_Client_t          *spk = Speaker_CreateClient(s);
DataSubscription_Client_t *ds  = DataSubscription_CreateClient(s);
Widget_Client_t           *w   = Widget_CreateClient(s);
```

client 内部会订阅该能力所需的 reply / event / osd topic，业务代码只需调用其提供的同步或异步 API，无需关心底层 topic 与 JSON 编解码。

## 发起调用

每个能力域下的接口分为四类调用形态：

| 类型 | 说明 | 典型 API 示例 |
|:---|:---|:---|
| **SERVICE** | 请求设备执行动作，等待应答 | `DataSubscription_SubscribeTopic(ds, &req, &resp, 5000)` |
| **PROPERTY** | 读取或设置设备参数 | `Widget_SetValue(w, &req, &resp, 5000)` |
| **EVENT** | 订阅偶发事件 | `Widget_OnFloatWindowMsg(w, cb, NULL)` |
| **OSD** | 订阅周期上报 | `DataSubscription_OnPublishData(ds, cb, NULL)` |

其中 SERVICE / PROPERTY 通常提供三套 API，可按场景选用：

- **同步**：`Widget_SetValue(w, &req, &resp, timeout)` — publish 后阻塞等待 reply。
- **异步**：`Widget_SetValueAsync(w, &req, cb, user)` — 注册回调后立即返回。
- **纯构造**：`Widget_BuildSetValuePayload(style, seq, &req)` — 仅生成 JSON 字符串，不执行 publish，适用于无 broker 时的单元测试或对接自定义 transport。

### SERVICE 调用示例

以数据订阅为例，订阅一个 FC 遥测 topic，再查询其最新值。该示例为只读操作，不会下发任何飞行控制指令，适合作为首次接入验证：

```c
/* 订阅一个 FC 遥测 topic */
T_DataSubscriptionSubscribeTopicRequest sub = {0};
sub.topic     = "quaternion";
sub.frequency = DATA_SUBSCRIPTION_FREQUENCY_1HZ;
T_ThingModelCommonReply sub_resp = {0};
T_ThingModelReturnCode rc = DataSubscription_SubscribeTopic(ds, &sub, &sub_resp, 5000);

/* 查询该 topic 最新值 */
T_DataSubscriptionGetLatestValueRequest q = {0};
q.topic = "quaternion";
T_ThingModelCommonReply q_resp = {0};
rc = DataSubscription_GetLatestValue(ds, &q, &q_resp, 5000);
printf("GetLatestValue rc=%d result=%d\n", rc, q_resp.result);
```

各能力域的完整 client 头文件位于 SDK 包内 `sdk/generated/c/<cap>/`，可据此查阅其提供的全部 SERVICE / PROPERTY / EVENT / OSD 接口。

## 编写第一个完整程序

将上述各步骤组合起来，即构成一个可运行的最小程序：连接 broker、创建 `DataSubscription` client、调用只读 SERVICE 完成首次验证。

```c
#include "thing_model_client/thing_model_client_session.h"
#include "thing_model_client/thing_model_client_osal.h"
#include "data_subscription/data_subscription_client.h"
#include "data_subscription/data_subscription_types.h"
#include "common/common_types.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static const char *envdef(const char *k, const char *d) {
    const char *v = getenv(k);
    return (v && *v) ? v : d;
}

int main(int argc, char **argv)
{
    (void)argc; (void)argv;

    /* 1. 注册 POSIX OSAL */
    ThingModelOsal_RegisterPosix();

    /* 2. 配置会话（优先从 THING_MODEL_* 环境变量读取） */
    ThingModelClientSession_Config_t cfg = {
        .app_id          = envdef("THING_MODEL_APP_ID",       "YOUR_APP_ID"),
        .app_name        = envdef("THING_MODEL_APP_NAME",     "psdkappfortest"),
        .app_key         = envdef("THING_MODEL_APP_KEY",      "YOUR_APP_KEY"),
        .app_license     = envdef("THING_MODEL_APP_LICENSE",  "YOUR_APP_LICENSE"),
        .device_sn       = envdef("THING_MODEL_DEVICE_SN",    "SN1234567890"),
        .broker_address  = envdef("THING_MODEL_BROKER",       "127.0.0.1"),
        .broker_port_tls = 8883,
        .broker_port     = 1883,
        .ca_cert_path    = envdef("THING_MODEL_CA_CERT_PATH", "/path/to/ca.crt"),
        .topic_style     = THING_MODEL_TOPIC_STYLE_V2,
    };

    ThingModelClientSession_t *s = ThingModelClientSession_Connect(&cfg);
    if (!s) {
        fprintf(stderr, "session connect failed\n");
        return 1;
    }

    /* 3. 创建 DataSubscription client */
    DataSubscription_Client_t *ds = DataSubscription_CreateClient(s);

    /* 4. 订阅一个 FC 遥测 topic */
    T_DataSubscriptionSubscribeTopicRequest sub = {0};
    sub.topic     = "quaternion";
    sub.frequency = DATA_SUBSCRIPTION_FREQUENCY_1HZ;
    T_ThingModelCommonReply sub_resp = {0};
    T_ThingModelReturnCode rc = DataSubscription_SubscribeTopic(ds, &sub, &sub_resp, 5000);
    if (rc != THING_MODEL_RC_OK) {
        printf("SubscribeTopic failed, rc=%d\n", rc);
    } else {
        printf("SubscribeTopic result=%d\n", sub_resp.result);
    }

    /* 5. 查询该 topic 最新值 */
    T_DataSubscriptionGetLatestValueRequest q = {0};
    q.topic = "quaternion";
    T_ThingModelCommonReply q_resp = {0};
    rc = DataSubscription_GetLatestValue(ds, &q, &q_resp, 5000);
    printf("GetLatestValue rc=%d result=%d\n", rc, q_resp.result);

    /* 6. 清理 */
    DataSubscription_DestroyClient(ds);
    ThingModelClientSession_Disconnect(s);
    return 0;
}
```

## 在自己的工程中集成 SDK

### 在示例工程基础上修改

建议先运行 SDK 包内 `projects/linux` 的完整示例，再在该工程下新增自有的 `.c` 文件：

1. 拷贝一个现有样例目录（如 `samples/data_subscription/`），重命名为你的负载能力目录。
2. 修改该目录下的 `CMakeLists.txt`，调整源码文件与可执行文件名。
3. 在顶层 `projects/linux/CMakeLists.txt` 中注册你的样例。
4. 编写 `src/your_client_demo.c`，可参考 `samples/data_subscription/src/data_subscription_client_demo.c` 或 `samples/widget/src/widget_client_demo.c`。

无 broker 时，也可先使用**纯构造 API** 验证 JSON 生成，再上真机调试。

### 独立 CMake 工程

如需在自有仓库中直接使用 SDK，可参照 <a href="#引入-sdk">引入 SDK</a> 中的 CMake 片段，将 `sdk/runtime/c` 与所需的 `sdk/generated/c/<cap>/` 加入工程，并按弱符号规则完成链接。更多说明请见 SDK 包内 `README.md`。

### 运行第一个可执行程序

完成代码编写后，在 SDK 包根目录进行构建。host（x86_64）编译用于快速验证 SDK 代码逻辑；若目标平台为 aarch64（如树莓派 4B、Manifold），请改用交叉编译（见 <a href="./quick-demo/raspberry-pi.html" target="_blank" rel="noopener noreferrer">树莓派快速体验</a>）。

```bash
cmake -B build_host -S projects/linux -DSAMPLE_BUILD=host
cmake --build build_host -j
./build_host/sample_things_model --list        # 列出本包中的样例
./build_host/sample_things_model data_subscription   # 首次验证推荐先跑数据订阅
```

## 调试技巧

### 查看每次调用的 topic 和 JSON

将日志级别设为 `debug` 后，stderr 会打印每条 publish 与所收消息的完整 topic 和 JSON，便于与飞机端协议对账：

```bash
export THING_MODEL_LOG_LEVEL=debug
./sample_things_model widget --debug
```

### 仅构造 JSON（不连接 broker）

使用纯构造 API，可在无 broker 的情况下先验证 payload 生成是否正确：

```c
T_WidgetSetValueRequest req = { .widget_index = 0, .widget_type = 1, .widget_value = 1 };
char *json = Widget_BuildSetValuePayload(THING_MODEL_TOPIC_STYLE_V2, 42, &req);
printf("%s\n", json);
free(json);
```

### 常见返回码

同步 API 返回 `T_ThingModelReturnCode`，表示 **SDK / 网络层**的调用结果：

| 值 | 含义 |
|:---|:---|
| `THING_MODEL_RC_OK` (0) | SDK 层调用成功，仍需检查 `resp.result` |
| `THING_MODEL_RC_TIMEOUT` (-3) | 设备未在 timeout 内回复 |
| `THING_MODEL_RC_TRANSPORT_ERROR` (-4) | MQTT 层错误，broker 不可达或连接被拒绝 |
| `THING_MODEL_RC_AUTH_FAILED` (-5) | 接入鉴权失败，请检查 App Key / License / SN / CA 证书 |

**业务层错误**体现为 `resp.result != 0`，需与返回码分两层判断：

```c
if (rc != THING_MODEL_RC_OK) {
    printf("SDK/network error: %d\n", rc);
} else if (resp.result != 0) {
    printf("Device rejected: %d %s\n", resp.result, resp.result_message);
} else {
    printf("OK\n");
}
```
