## 简介

本文通过一个基于 **E‑Port V3 开发套件**的快速体验 Demo，帮助开发者在最短时间内完成从负载硬件接入、PSDK 示例配置到 Demo 运行验证的完整流程。  
通过该 Demo，开发者可以快速了解**基于 PSDK 的负载开发方式**，并掌握负载设备如何通过 E‑Port V3 接口与飞行平台及 DJI Pilot 建立通信与交互。

## 通过本 Demo 你将完成什么
完成本快速体验 Demo 后，你将能够：
- 使用 E‑Port V3 开发板作为负载设备，与飞行平台进行硬件连接。  
- 在 GD32F527 板载 MCU 上运行 PSDK 示例程序。  
- 成功运行负载 Demo 程序，并与飞行平台建立通信。  
- 在 DJI Pilot 上验证负载被正确识别，并完成基础交互验证。  

## E‑Port V3 开发套件介绍
E-Port V3 开发套件方便开发者快速启动基于 E-Port V3 接口的 PSDK 负载开发，到手开箱即用。可将 E-Port V3 接口转接成常见的通信接口和电源接口，方便开发调试。  
E-Port V3 开发板内置 MCU，MCU 型号为 GD32F527ZMT7，外扩 8 MB SDRAM，其器件规格与技术文档可从 GD32 官网获取。  
E-Port V3 开发板同时兼容 E-Port V2 接口，可通过开发板上的切换开关选择使用 E-Port V2 或 E-Port V3 接口模式。  
通过开关（图示 11）可以切换连接到外置设备，需将外置设备连接到 USB 接口（图示 12），该 USB 可连接至第三方 MCU 或 SoC 开发板设备的 USB Device 接口。

:::tip 说明：
最低版本要求：不低于 PSDK V4.0.0
:::

* 电源开关（ENABLE 丝印）：通过拨码 ON 或者 OFF 控制飞机电源输入，开关旁边是绿色的电源指示灯。
* 复位按键：右下角丝印为 RESET 的按键，用于 MCU 复位。
* 烧录接口：右下角复位按键旁边丝印为 SDIO 的引脚，支持 SWD 接口烧录 MCU 芯片。
* 调试串口：右下角 Debug 丝印的四个引脚，其中 TX/RX 分别对应 MCU 的 PA0/PA1引脚。
* 功率电源输出：3个 XT30接口，分别能给出5V/12V/VCC 电压的功率输出。
* 板载认证芯片使能开关：丝印为 JM，用于选择认证芯片来源。默认拨至 N，使用 E-Port V3 同轴线内置的认证芯片；拨至 Y 时，使用开发板板载认证芯片，适用于自行制作线材或验证自制线材的场景。
* Loader 按键：左下角丝印为 Loader，可以在复位时强制进入 MCU 的 Loader 进行升级（需要烧录配套的 Loader 固件）
* SWITCH 开关：USB 信号选择开关，当开关切换到 ONBOARD 时，E-Port 口的 USB 2.0 信号连通到 MCU，此时可作为开发板开发 PSDK 设备；当开关切换到 EXPAND 端，E-Port 口的 USB 2.0/3.0 信号可以连通到 Type-A 口上，此时可以作为转接板，接入外部的 PSDK 设备进行二次开发。
* USB 接口：飞机作为 Host，板载 MCU/扩展外部设备的 USB 作为 Device。
* 扩展 IO：在调试串口旁边有一排扩展 IO，引脚定义如下，可结合实际情况灵活使用。

### Matrice 5TD 设备连接

Matrice 5TD 的 E-Port V3 接口均支持连接负载设备，其中 E1 为高速接口（支持 USB 3.0），E2/E3 为低速接口（支持 USB 2.0）。下图以连接 E3 低速接口为例；如需使用高速数据能力，请连接 E1 高速接口。接口说明请参见 <a href="../configure-the-hardware-environment/drone-port.html#e-port-v3-接口" target="_blank" rel="noopener noreferrer">E-Port V3 接口</a>。  
连接前请将开发板上的接口切换开关拨到 **E-Port V3** 模式。使用 E-Port V3 同轴线将 E‑Port V3 开发板连接至 Matrice 5TD 的 E‑Port V3 接口。

进入 <a href="https://developer.dji.com/cn/payload-sdk/downloads/" target="_blank" rel="noopener noreferrer">开发者中心下载页面</a>，在 **Payload Certificate** 处点击“下载”，获取 TLS CA 证书（`ca.crt`）。该证书用于校验 MQTT broker 的服务器身份。RTOS 示例工程已将该证书内嵌在 `projects/rtos/gd32f527/network/tls/ca_cert.h`，可直接使用；自有工程以同样的方式将 CA 以 C 数组内嵌即可，可参考 `projects/rtos/gd32f527/app/ca_cert_provider.c`。

## 运行 Demo

在开始前，请先按 <a href="../config-develop-environment.html" target="_blank" rel="noopener noreferrer">配置开发环境</a> 完成 RTOS 工具链（Keil MDK、GD32F527 驱动包）安装。若想进一步了解 SDK 侧代码如何调用负载能力，可参考 <a href="../getting-started-with-psdk.html" target="_blank" rel="noopener noreferrer">开始使用 PSDK</a>。

获取 PSDK 源码：

```bash
git clone https://github.com/dji-sdk/Payload-SDK-V4.git
cd Payload-SDK-V4
```

使用 E-Port V3 开发板（GD32F527 等 MCU）时，需把示例集成到你的 RTOS/裸机工程。核心步骤：

1. **整理源码**：将 `samples/launcher/`、所需样例的 `samples/<能力>/src/*.c`、`sdk/generated/c/` 下的协议代码，以及 `sdk/runtime/c/src/`（不含 POSIX/mosquitto 桌面实现）加入工程。
2. **实现平台胶**：
   - 实现 `T_ThingModelOsal`（线程、锁、事件、延时）；
   - 实现 MQTT transport vtable 与 HMAC-SHA256 crypto vtable（或使用平台已有库）；
   - 将 `printf` 重定向到 UART。
3. **补充应用信息**：将上一步 <a href="#获取应用信息">获取应用信息</a> 得到的信息填入 `projects/rtos/gd32f527/app/sample_config_local.h`（由 `sample_config_local.h.example` 拷贝而来）。RTOS 侧的宏名与 Linux 侧不同：

   | 配置项 | 类型 | 必填 | 含义与填写方式 |
   |:---|:---|:---|:---|
   | SAMPLE_APP_ID | string | 是 | 应用 ID，填写平台分配的字符串。 |
   | SAMPLE_APP_NAME | string | 否 | 应用名称，即创建应用时填写的名称（如 `psdkappfortest`）。服务器据此识别应用身份，建议填写。 |
   | SAMPLE_APP_KEY | string | 是 | 应用密钥，请妥善保管，勿硬编码进版本库。 |
   | SAMPLE_APP_LICENSE | string | 是 | 应用授权码。 |
   | SAMPLE_DEVICE_SN | string | 是 | 负载设备序列号，由负载开发者自定义（**非飞机 SN**），用于标识接入的负载，同时作为 MQTT 连接标识及各业务 Topic 中的 `{client_id}`。<br>格式要求：由数字、字母、下划线（`_`）组成，长度不超过 64 个字符；请保证每台负载设备使用不同的 SN。 |
   | SAMPLE_BROKER_ADDR | string | 是 | 飞机端 broker 的地址。按飞机型号填写，例如 Matrice 5TD 为 `192.168.100.3`。 |
   | SAMPLE_BROKER_PORT_TLS | number | 是 | 两阶段鉴权中 TLS 连接使用的端口，默认 8883。 |
   | SAMPLE_BROKER_PORT | number | 是 | token 鉴权后普通 MQTT 连接使用的端口，默认 1883。 |

   RTOS 侧的 CA 证书以 C 数组内嵌在固件中，无需配置（证书位置：`projects/rtos/gd32f527/network/tls/ca_cert.h`）。证书来源与放置方式见 <a href="#下载证书">下载证书</a>。
4. **选择前门**：定义 `SAMPLE_AUTORUN_ALL=1`（轮播全部）或 `SAMPLE_AUTORUN="widget"`（只跑一个）。
5. **启动**：在任务里调用 `sample_launcher_run(0, NULL)`。

详细移植说明请见 SDK 包内 `samples/launcher/sample_launcher.h` 的头部注释，以及 `projects/rtos/gd32f527/` 参考工程。

## 应用绑定

负载设备接入 MQTT broker 后，须先完成**应用绑定**，飞机端才会放行业务请求。设备未绑定时，飞机端会在事件通道推送 `bind_required` 通知，并拒绝处理喊话器、自定义控件等业务功能。绑定概念与流程详见 <a href="../app-bind.html" target="_blank" rel="noopener noreferrer">应用绑定</a>。

运行 Demo 前请确认：

1. 负载设备已通过鉴权成功接入 broker。
2. 通过 DJI Assistant 2 完成设备绑定。
3. Demo 程序监听绑定状态，确认 `bind_state` 为已绑定后再启动业务功能。

绑定状态通知与查询的接口用法详见 <a href="../../function-set/bind.html" target="_blank" rel="noopener noreferrer">功能集合-绑定状态通知</a>。
