

## 简介
本文通过一个基于 **树莓派 4B 开发板** 的快速体验 Demo，引导开发者在最短时间内完成从硬件连接、PSDK 环境准备、示例程序配置到 Demo 运行验证的完整流程。

:::tip 说明：
最低版本要求：不低于 PSDK V4.0.0
:::

## 通过本 Demo 你将完成什么
完成本快速体验 Demo 后，你将能够：
- 使用 **树莓派 4B** 作为外部 Linux 负载设备。  
- 通过 **E‑Port V3 开发板** 将树莓派开发板接入 Matrice 5TD 飞行平台。

如下是本篇教程需要使用的硬件设备介绍，建议您在查看后续内容前进行相关阅读。

* E‑Port V3 开发者套件


## 硬件环境准备
### 设备连接

#### Matrice 5TD 设备连接
##### 基于 E-Port V3 接口连接设备

Matrice 5TD 的 E-Port V3 接口均支持连接负载设备，其中 E1 为高速接口（支持 USB 3.0），E2/E3 为低速接口（支持 USB 2.0）。下图以连接 E3 低速接口为例；如需使用高速数据能力，请连接 E1 高速接口。接口说明请参见 <a href="../configure-the-hardware-environment/drone-port.html#e-port-v3-接口" target="_blank" rel="noopener noreferrer">E-Port V3 接口</a>。

1. 将 E-Port V3 开发板上的接口切换开关拨至 "E-PORT V3" 端。
2. 将 E-Port V3 开发板的 ENABLE 开关拨到 "ON"，SWITCH 开关拨到 "EXPAND" 端。
3. 使用 E-Port V3 同轴线连接 E-Port V3 开发板与 Matrice 5TD 机身的 E-Port V3 接口。
4. 将树莓派 4B 开发板烧录好官方系统镜像后，通过 USB 线连接 E-Port V3 开发板的 USB 接口与树莓派 4B 开发板的供电接口（包含 USB 2.0 的通讯能力）。
5. 无人机整机启动，检查 E-Port V3 开发板绿色电源指示灯是否亮起，树莓派是否启动正常。

## 软件环境准备
### 安装软件环境
1. 树莓派 4B 开发套件默认不包含 SD 卡和 Raspberry Pi OS 64 位系统镜像，请参考 [树莓派烧录指导](https://shumeipai.nxez.com/2013/09/07/how-to-install-and-activate-raspberry-pi.html)  进行镜像烧录和账户配置。
2. 完成[硬件环境准备](#硬件环境准备)并启动完成后，输入配置的账号密码，检查是否可以登录进入 Raspberry Pi 桌面系统。
3. 进入桌面后，您可以通过浏览器访问网页检查 树莓派 4B 开发网络环境是否正常。
4. 在运行 PSDK 之前，需要安装 OpenSSL、Mosquitto、cJSON、Mongoose 等依赖库。请参考下文的 shell 命令完成安装，并检查是否安装成功。

#### 目标树莓派安装运行时依赖
在树莓派上，示例程序启动时需要以下动态库（OpenSSL、Mosquitto、cJSON）：

```bash
sudo apt-get update
sudo apt-get install -y libssl3 libmosquitto1 libcjson1
```

如果后续运行时报缺少 `libmosquitto.so.1` / `libssl.so.3`，请按实际包名补装对应版本。

#### 编译主机安装构建依赖
在用于交叉编译的主机（PC）上需要安装工具链与头文件依赖：

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake python3 zip git
sudo apt-get install -y gcc-aarch64-linux-gnu
sudo apt-get install -y libssl-dev libmosquitto-dev libcjson-dev
```

> 说明：交叉编译时链接的是目标架构（aarch64）的动态库，但 CMake 构建仍需要 host 上的 OpenSSL / mosquitto 头文件。`libmongoose-dev` 多数发行版没有系统包，若编译 widget 样例，需手动提供 mongoose 源码；不启用 widget/upgrade 的 HTTP 文件服务则可跳过。完整的工具链版本要求见 <a href="../config-develop-environment.html#配置-linux-开发环境" target="_blank" rel="noopener noreferrer">配置开发环境 - 配置 Linux 开发环境</a>。


### 开启树莓派 4B 的 USB 设备功能

您可以参考 [树莓派 bulk 端点配置指导](https://sdk-forum.dji.net/hc/zh-cn/articles/10232604141465-M30%E5%BC%80%E5%8F%91-%E6%A0%91%E8%8E%93%E6%B4%BE4B%E9%85%8D%E7%BD%AEUSB-device-RNDIS-%E5%92%8C-BULK) 开启树莓派 4B 的 USB 设备功能。
:::tip 说明:
您需要将`raspi-usb-device-start.sh`替换为以下内容。
- 将 VID:PID 设置为 2CA3:F004。<br>
:::

```shell
#!/bin/bash

# The IP address shared by all USB network interfaces created by this script.
net_ip=192.168.42.120
# The associated netmask.
net_mask=255.255.0.0

enable_vcom=0
enable_rndis=0
enable_bulk=1

startup_bulk_dir=$(dirname "$0")
startup_bulk_exe=${startup_bulk_dir}/build/startup_bulk

if [ ! -d /sys/kernel/config/usb_gadget ]; then
    if ! $(grep -q dtoverlay=dwc2 /boot/config.txt) ; then
        echo -e "\n\n\n## customized\n# for op-sdk enable USB device RNDIS\n[all]\ndtoverlay=dwc2" >> /boot/config.txt
        init 6
    fi

    if ! $(grep -q modules-load=dwc2 /boot/cmdline.txt) ; then
        sed -i 's/rootwait /&modules-load=dwc2 /' /boot/cmdline.txt
        init 6
    fi

    if ! $(grep -q libcomposite /etc/modules) ; then
        echo -e "\n\n\n## customized\n# for op-sdk enable USB device RNDIS\nlibcomposite" >> /etc/modules
        init 6
    fi

    exit 1
fi

modprobe g_ether
rmmod g_ether
sleep 1

if [ ! -d /sys/kernel/config/usb_gadget/pi4 ]; then
    mkdir -p /sys/kernel/config/usb_gadget/pi4
    cd /sys/kernel/config/usb_gadget/pi4
        echo 0x2ca3 > idVendor # DJI
        echo 0xF004 > idProduct # Multifunction Composite Gadget

        if [ ${enable_vcom} -eq 1 ]; then
            echo 0xF004 > idProduct # Multifunction Composite Gadget
        fi

        if [ ${enable_rndis} -eq 1 ]; then
            echo 0xF004 > idProduct # Multifunction Composite Gadget
        fi

        if [ ${enable_bulk} -eq 1 ]; then
            echo 0xF004 > idProduct # Multifunction Composite Gadget
        fi

        echo 0x0001 > bcdDevice # v1.0.0
        echo 0x0200 > bcdUSB # USB2

        echo 0xEF > bDeviceClass
        echo 0x02 > bDeviceSubClass
        echo 0x01 > bDeviceProtocol

        mkdir -p strings/0x409
            echo "psdk-rpi4b" > strings/0x409/serialnumber
            echo "raspberry" > strings/0x409/manufacturer
            echo "PI4" > strings/0x409/product

        cfg=configs/c.1

        mkdir -p "${cfg}"
            echo 0x80 > ${cfg}/bmAttributes
            echo 250 > ${cfg}/MaxPower

        cfg_str=""

        if [ ${enable_rndis} -eq 1 ]; then
            cfg_str="${cfg_str}+RNDIS"
            func=functions/rndis.usb0
            mkdir -p "${func}"
                ln -sf "${func}" "${cfg}"

            # Informs Windows that this device is compatible with the built-in RNDIS
            # driver. This allows automatic driver installation without any need for
            # a .inf file or manual driver selection.
            echo 1 > os_desc/use
            echo 0xcd > os_desc/b_vendor_code
            echo MSFT100 > os_desc/qw_sign
                echo RNDIS > "${func}/os_desc/interface.rndis/compatible_id"
                echo 5162001 > "${func}/os_desc/interface.rndis/sub_compatible_id"

            ln -sf "${cfg}" os_desc
        fi

        if [ ${enable_vcom} -eq 1 ]; then
            cfg_str="${cfg_str}+ACM0"
            func=functions/acm.gs0
            mkdir -p "${func}"
            ln -sf "${func}" "${cfg}"
        fi

        if [ ${enable_bulk} -eq 1 ]; then
            mkdir -p /dev/usb-ffs

            cfg_str="${cfg_str}+BULK1"
            mkdir -p /dev/usb-ffs/bulk1
            func=functions/ffs.bulk1
            mkdir -p "${func}"
            ln -sf "${func}" "${cfg}"
            mount -o mode=0777,uid=2000,gid=2000 -t functionfs bulk1 /dev/usb-ffs/bulk1

            cfg_str="${cfg_str}+BULK2"
            mkdir -p /dev/usb-ffs/bulk2
            func=functions/ffs.bulk2
            mkdir -p "${func}"
            ln -sf "${func}" "${cfg}"
            mount -o mode=0777,uid=2000,gid=2000 -t functionfs bulk2 /dev/usb-ffs/bulk2

            cfg_str="${cfg_str}+BULK3"
            mkdir -p /dev/usb-ffs/bulk3
            func=functions/ffs.bulk3
            mkdir -p "${func}"
            ln -sf "${func}" "${cfg}"
            mount -o mode=0777,uid=2000,gid=2000 -t functionfs bulk3 /dev/usb-ffs/bulk3
        fi

        mkdir -p "${cfg}/strings/0x409"
        echo "${cfg_str:1}" > "${cfg}/strings/0x409/configuration"
    # cd -

fi

if [ ${enable_bulk} -eq 1 ]; then
    if [ ! -f ${startup_bulk_exe} ]; then
        cd ${startup_bulk_dir}
            make && ( $? != 0 ) && ( exit 1 )
            cp startup_bulk ${startup_bulk_exe}
            make clean
        cd -
    fi

    ${startup_bulk_exe} /dev/usb-ffs/bulk1 &
    sleep 1
    ${startup_bulk_exe} /dev/usb-ffs/bulk2 &
    sleep 1
    ${startup_bulk_exe} /dev/usb-ffs/bulk3 &
    sleep 1
fi

    udevadm settle -t 5 || :
    ls /sys/class/udc > UDC

if [ ${enable_rndis} -eq 1 ]; then
    /sbin/brctl addbr pi4br0
    /sbin/ifconfig pi4br0 ${net_ip} netmask ${net_mask} up

    /sbin/brctl addif pi4br0 usb0
    /sbin/ifconfig usb0 down
    /sbin/ifconfig usb0 up
fi
exit 0

```

### 配置网络连接

负载程序需通过飞机端 broker 通信，运行前需先连通树莓派与飞机的网络。树莓派通过 USB 网络（网卡 `usb0`）与飞机相连，其 IP 由飞机通过 DHCP 分配。由于不同负载口分配的网段不同，IP 需在设备上动态读取，不应硬编码。

:::tip 说明：
`usb0` 归属于网桥 `pi4br0`，实际的网络通信由 `pi4br0` 负责。因此需将飞机分配的 IP 与路由配置到 `pi4br0` 上，`usb0` 保持不变。以下步骤均需 root 权限（`sudo`），每次系统启动后执行一次即可。
:::

#### 1. 获取 IP 与网关

在 `usb0` 上触发 DHCP，向飞机申请 IP：

```text
sudo dhclient -v usb0        # 输出中出现 DHCPACK 即申请成功
```

申请成功后，读取飞机分配的 IP（含掩码）与网关，供后续步骤使用。

读取 IP 与掩码：

```text
ip -4 -o addr show dev usb0
```

输出类似 `inet 192.168.150.2/24 ...`，其中 `192.168.150.2` 为 IP、`/24` 为掩码。

读取网关（默认路由中 `via` 后的地址）：

```text
ip -4 -o route show default dev usb0
```

输出类似 `default via 192.168.150.1 dev usb0 proto dhcp src 192.168.150.2 ...`，其中 `192.168.150.1` 为网关。

上例中，IP 为 `192.168.150.2/24`，网关为 `192.168.150.1`；实际取值以设备读取结果为准。

#### 2. 将 IP 配置到网桥

移除 `usb0` 上的 IP，并配置到 `pi4br0`：

```text
sudo ip addr del 192.168.150.2/24 dev usb0
sudo ip addr add 192.168.150.2/24 dev pi4br0
```

#### 3. 配置路由

配置一条到 broker 网段的路由，使树莓派能访问 broker。以 Matrice 5TD 为例（broker 网段 `192.168.100.0/24`，broker 地址 `192.168.100.3`），实际请按所用机型替换。

`pi4br0` 上可能存在多个 IP，需通过 `src` 指定飞机网段的 IP 作为源地址：

```text
sudo ip route add 192.168.100.0/24 via 192.168.150.1 dev pi4br0 src 192.168.150.2
```

#### 4. 验证连通性

执行以下命令，若能 ping 通 broker 地址即表示网络就绪，可继续运行负载程序：

```text
ping -c 3 192.168.100.3
```

cd build_aarch64

## 应用绑定

负载设备接入 MQTT broker 后，须先完成**应用绑定**，飞机端才会放行业务请求。设备未绑定时，飞机端会在事件通道推送 `bind_required` 通知，并拒绝处理喊话器、自定义控件等业务功能。绑定概念与流程详见 <a href="../app-bind.html" target="_blank" rel="noopener noreferrer">应用绑定</a>。

运行 Demo 前请确认：

1. 负载设备已通过鉴权成功接入 broker。
2. 通过 DJI Assistant 2 完成设备绑定。
3. Demo 程序监听绑定状态，确认 `bind_state` 为已绑定后再启动业务功能。

绑定状态通知与查询的接口用法详见 <a href="../../function-set/bind.html" target="_blank" rel="noopener noreferrer">功能集合-绑定状态通知</a>。
