## Overview

:::warning Warning:
For the Matrice 5TD model, only one payload port is allowed to enable and use the EFTS feature at any given time. If multiple payload ports use EFTS simultaneously, the flight platform may falsely detect the PWM signal, causing the EFTS feature to malfunction. Please ensure that only one payload port on the entire aircraft enables EFTS.
:::

The emergency landing feature is implemented through the Emergency Flight Termination System (EFTS). EFTS is the hardware implementation of the Flight Termination System (FTS). It triggers the flight platform to stop propellers through the PWM signal output by the payload hardware, without relying on the software command link.

The payload can enable the flight controller-side FTS PWM trigger port on the ground, and can also query the FTS PWM trigger status.

:::tip Note:
- The C interfaces in PSDK encapsulate the underlying MQTT protocol. Developers can complete protocol interactions by calling the C interfaces directly, without manually constructing MQTT messages. For MQTT payload structures and field definitions, see <a href="../api-reference/api-eu-c6.html" target="_blank" rel="noopener noreferrer">Protocol Reference - GEO Caging</a>.
- Before using this feature, the payload device must first complete access and authentication. For details, see <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Basic Concepts

### Terminology

**Flight Termination System (FTS)**

A set of equipment and software that actively and forcibly terminates flight when a safety hazard occurs during flight, and is independent of the aircraft's own control system.

**Emergency Flight Termination System (EFTS)**

EFTS is the hardware implementation of FTS. The payload device actively outputs a PWM signal that meets the specifications to the flight platform through the port. After the flight platform detects that the signal meets the conditions, it immediately executes the motor propeller stop operation, without relying on the software command link.

### Model Support and Hardware Signal Requirements

The payload device needs to output a compliant PWM signal to the FTS pin of the specified port according to the parameters of the corresponding model in the table below:

| Model | Supported Port | PWM Frequency | Duty Cycle | Voltage |
|------|---------|---------|--------|------|
| Matrice 5TD | FTS pin of E-Port V3 port | 400 Hz | 50% | 3.3 V |

:::warning Warning:
- Matrice 5TD model constraints:
  - The EFTS feature cannot be used simultaneously with features based on the PPS signal (such as the PPS signal source for time synchronization). If a feature based on the PPS signal is already enabled, you must first disable it and re-plug the payload before using the EFTS feature.
  - Only one payload port can send PWM waves to the aircraft to trigger the EFTS feature at any given time; otherwise, the emergency landing feature may not work properly.
:::

## Feature Introduction

:::warning Warning:
The following code is for reference only and demonstrates the call flow and implementation of each feature. Developers can adapt it based on the hardware characteristics and application scenarios of the payload device.
:::

### Create Client

Create an EFTS client on the established MQTT session `s`. Subsequent interfaces are all called through this client.

```c
Efts_Client_t *efts = Efts_CreateClient(s);
```

### Enable FTS PWM Trigger Port

Enable the flight controller-side FTS PWM trigger port on the ground. This interface only enables the trigger port; it does not emit a PWM signal, nor does it perform a propeller stop action. The actual propeller stop is triggered by external PWM hardware outputting a PWM signal that meets the specifications to this port. For the corresponding MQTT protocol, see <a href="../api-reference/api-eu-c6.html#enable-fts-pwm-trigger-port" target="_blank" rel="noopener noreferrer">Enable FTS PWM Trigger Port</a>.

```c
T_ThingModelCommonReply resp = {0};
T_ThingModelReturnCode rc = Efts_SelectFtsPwmTrigger(efts, NULL, &resp, 5000);
if (rc == THING_MODEL_RC_OK && resp.result == 0) {
    USER_LOG_INFO("select fts pwm trigger success.");
} else {
    USER_LOG_ERROR("select fts pwm trigger failed: rc=%d result=%d msg=%s",
                   rc, resp.result, resp.result_message);
}
```

:::tip Note:
This interface has no input parameters. When calling, pass `NULL` for `req` (`data` is an empty object `{}`).
:::

#### Example: Outputting the PWM Trigger Signal on Raspberry Pi

After the trigger port is enabled, external hardware must also output a PWM signal that meets the specifications to the FTS pin before the flight platform will stop the propellers. The following example uses a Raspberry Pi (Raspberry Pi 4B) to output a 400 Hz square wave with a 50% duty cycle on GPIO 18, simulating the payload's PWM trigger signal. The example uses the SoC's on-chip hardware PWM (`/sys/class/pwm`) rather than software-simulated PWM, to ensure a stable frequency and duty cycle.

:::warning Warning:
On the Raspberry Pi 4B, the hardware PWM channel on GPIO 18 is occupied by the onboard audio function by default. Before first use, you need to modify `/boot/config.txt` and reboot to complete a one-time configuration:

1. Change `dtparam=audio=on` to `dtparam=audio=off` to release the hardware PWM channel.
2. Append the following line at the end of the file to repurpose GPIO 18 and 19 as hardware PWM outputs:

```
dtoverlay=pwm-2chan,pin=18,func=2,pin2=19,func2=2
```

3. Save the file and reboot the Raspberry Pi for the configuration to take effect.

Once the configuration takes effect, a `pwmchip0` device node will appear under `/sys/class/pwm/`. Running the example will produce a 400 Hz square wave observable on GPIO 18.
:::

The example code exports, configures, and enables the PWM channel by operating the `/sys/class/pwm/pwmchip0` node:

```shell
# Export PWM channel 0 (corresponding to GPIO 18)
echo 0 > /sys/class/pwm/pwmchip0/export

# Configure the period and duty cycle, in nanoseconds
# 400 Hz -> period 2500000 ns, 50% duty cycle -> high level duration 1250000 ns
echo 2500000 > /sys/class/pwm/pwmchip0/pwm0/period
echo 1250000 > /sys/class/pwm/pwmchip0/pwm0/duty_cycle

# Enable PWM output
echo 1 > /sys/class/pwm/pwmchip0/pwm0/enable
```

:::tip Note:
- The shell commands above are only meant to illustrate the configuration flow. In the EFTS sample, this has already been wrapped into a ready-to-run program that, once started, continuously outputs a 400 Hz, 50% duty cycle square wave on GPIO 18 that meets the Matrice 5TD model's requirements.
- To stop the output, write `0` to `enable`, and write the channel number to `unexport` to release the resource.
- This square wave is only intended for locally verifying the EFTS hardware trigger link. In actual use, the payload device must connect an equivalent PWM signal, based on its own hardware conditions, to the FTS pin specified by the flight platform.
:::

### Query FTS PWM Trigger Status

Query the current FTS PWM trigger status and the cumulative number of correctly received PWM propeller stop signals. If you need to confirm the effect of the propeller stop execution, you can also subscribe to the flight controller ESC data and verify it through the ESC speed. For the corresponding MQTT protocol, see <a href="../api-reference/api-eu-c6.html#query-fts-pwm-trigger-status" target="_blank" rel="noopener noreferrer">Query FTS PWM Trigger Status</a>.

```c
T_EftsGetFtsTriggerStatusReply r = {0};
T_ThingModelReturnCode rc = Efts_GetFtsTriggerStatus(efts, NULL, &r, 5000);
if (rc == THING_MODEL_RC_OK && r.result == 0) {
    USER_LOG_INFO("fts_status=%d  fts_pwm_cnt=%d", (int)r.fts_status, r.fts_pwm_cnt);
} else {
    USER_LOG_ERROR("get fts trigger status failed: rc=%d result=%d msg=%s",
                   rc, r.result, r.result_message);
}
```

Field descriptions of the reply structure `T_EftsGetFtsTriggerStatusReply`:

| Field | Type | Description |
|------|------|------|
| result | int32_t | Processing result, 0 indicates success |
| result_message | char * | Result description information |
| fts_status | E_EftsFtsStatus | FTS PWM trigger status.<ul><li>EFTS_FTS_STATUS_NOT_TRIGGERED (0): not triggered</li><li>EFTS_FTS_STATUS_TRIGGERED (1): triggered</li></ul> |
| fts_pwm_cnt | int32_t | Cumulative number of correctly received PWM propeller stop signals |

### Destroy Client

When the EFTS feature is no longer used, destroy the client to release resources.

```c
Efts_DestroyClient(efts);
```
