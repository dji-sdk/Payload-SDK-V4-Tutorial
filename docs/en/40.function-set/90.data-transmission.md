## Overview

Data transmission is used to transparently transmit small custom data between a payload and the cloud, or between payloads. Data is routed and forwarded by the aircraft, with a maximum of 256 bytes per message, suitable for scenarios such as small-volume telemetry reporting and inter-payload communication.

The payload sends data to a target device through the publisher, and receives data forwarded by the aircraft from other devices by registering a callback through the client. Both sending and receiving go through the event channel, without request/response.

:::tip Note:
- The C interfaces in PSDK encapsulate the underlying MQTT protocol. Developers can complete protocol interactions by calling the C interfaces directly, without manually constructing MQTT messages. For MQTT payload structures and field definitions, see <a href="../api-reference/api-data-transmission.html" target="_blank" rel="noopener noreferrer">Protocol Reference - Data Transmission</a>.
- Before using this feature, the payload device must first complete access and authentication. For details, see <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Basic Concepts

### Terminology

**Channel Address**

Identifies the device endpoint for data sending and receiving. When sending, it is used to specify the target device; when receiving, it indicates the source device of the data. Values cover payload 1/2/3 and the cloud.

**Publisher**

The payload-side object used to actively send data to a target device. The aircraft routes the data to the target device.

**Client**

The payload-side object used to receive data sent from other devices. The payload registers a handler callback, and data forwarded by the aircraft from other devices is delivered to the payload through the SDK callback.

### Channel Address Values

Both the target address for sending data and the source address for receiving data use the channel address enum `E_ChannelAddress`, with the following values:

| Enum Constant | Value | Meaning |
|------|------|------|
| CHANNEL_ADDRESS_PAYLOAD_NO1 | 1 | Payload position 1 |
| CHANNEL_ADDRESS_PAYLOAD_NO2 | 2 | Payload position 2 |
| CHANNEL_ADDRESS_PAYLOAD_NO3 | 3 | Payload position 3 |
| CHANNEL_ADDRESS_CLOUD | 15 | Cloud |

:::warning Warning:
The `payload` of a single transparent transmission message is at most 256 bytes; excess may be truncated or discarded. The receive callback is triggered on a background thread. Synchronous APIs should not be called within the callback, and the client or publisher should not be destroyed within it; time-consuming logic should be handed off to other threads. If data is sent back to the source device within the receive callback, care must be taken to avoid the sender and receiver replying to each other, forming an infinite loop.
:::

## Feature Introduction

:::warning Warning:
The following code is for reference only and demonstrates the call flow and implementation of each feature. Developers can adapt it based on the hardware characteristics and application scenarios of the payload device.
:::

### Create Client and Publisher

Create the data transmission client and publisher on the established MQTT session `session`. Data is received through the callback registered by the client, and data is sent through the publisher.

```c
CustomSmallData_Client_t    *client    = CustomSmallData_CreateClient(session);
CustomSmallData_Publisher_t *publisher = CustomSmallData_CreatePublisher(session);
```

### Receive Data

Register a callback to receive data forwarded by the aircraft from other devices. The callback is triggered when data is received. The parameter `push` points to the decoded received data structure, in which `source` is the source device address and `payload` is the transparent transmission data. For the corresponding MQTT protocol, see <a href="../api-reference/api-data-transmission.html#receive-data" target="_blank" rel="noopener noreferrer">Receive Data</a>.

```c
static void on_transmit_push(void *user, const T_TransmitEventPush *push)
{
    if (!push) return;
    USER_LOG_INFO("recv from %d, len=%u, data=%.*s",
                  push->source, (unsigned)push->payload.len,
                  (int)push->payload.len, (const char *)push->payload.data);
}

T_ThingModelReturnCode rc = CustomSmallData_OnTransmitPush(client, on_transmit_push, NULL);
if (rc != THING_MODEL_RC_OK) {
    USER_LOG_ERROR("register transmit push callback failed: rc=%d", rc);
}
```

Field descriptions of the receive structure `T_TransmitEventPush`:

| Field | Type | Description |
|------|------|------|
| source | E_ChannelAddress | Data source, i.e., the device that sent the transparent transmission data.<ul><li>CHANNEL_ADDRESS_PAYLOAD_NO1: Payload position 1</li><li>CHANNEL_ADDRESS_PAYLOAD_NO2: Payload position 2</li><li>CHANNEL_ADDRESS_PAYLOAD_NO3: Payload position 3</li><li>CHANNEL_ADDRESS_CLOUD: Cloud</li></ul> |
| payload.data | uint8_t * | Pointer to the transparent transmission data buffer |
| payload.len | size_t | Number of bytes of transparent transmission data, maximum 256 |

:::warning Warning:
The callback is triggered on a background thread. Synchronous APIs should not be called within the callback, and the client or publisher should not be destroyed within it. The buffer pointed to by `push->payload.data` is only valid during the callback; if the data needs to be retained, it should be copied within the callback.
:::

### Send Data

Send a piece of small data to a specified target device. Before calling, first initialize the request structure with `CustomSmallData_InitTransmitRequest()`, then set the target address `target` and the transparent transmission data `payload`. For the corresponding MQTT protocol, see <a href="../api-reference/api-data-transmission.html#send-data" target="_blank" rel="noopener noreferrer">Send Data</a>.

```c
const char *msg = "hello cloud";

T_TransmitRequest req;
CustomSmallData_InitTransmitRequest(&req);
req.target       = CHANNEL_ADDRESS_CLOUD;
req.payload.data = (uint8_t *)msg;
req.payload.len  = strlen(msg) + 1;

T_ThingModelReturnCode rc = CustomSmallData_PublishTransmit(publisher, &req);
if (rc != THING_MODEL_RC_OK) {
    USER_LOG_ERROR("transmit failed: rc=%d", rc);
}
```

Field descriptions of the request structure `T_TransmitRequest`:

| Field | Type | Description |
|------|------|------|
| target | E_ChannelAddress | Target device channel address. For values, see [Channel Address Values](#channel-address-values) |
| payload.data | uint8_t * | Pointer to the buffer of data to be sent |
| payload.len | size_t | Number of bytes of data to be sent, maximum 256 |

:::tip Note:
This interface is an event send, using fire-and-forget semantics, with no aircraft acknowledgment; the return code `rc` only indicates whether the local send was successfully submitted, and does not mean the target device has received it.
:::

### Destroy Client and Publisher

When the data transmission feature is no longer used, destroy the client and publisher to release resources. The session should be disconnected before destroying the client and publisher, to avoid in-flight message callbacks accessing already-released objects.

```c
CustomSmallData_DestroyPublisher(publisher);
CustomSmallData_DestroyClient(client);
```
