## Overview

Aircraft Information allows the payload to obtain the model, firmware version, mobile app configuration, and onboard device list of the currently mounted aircraft. After the device connects to the MQTT server, the aircraft periodically pushes the `aircraft_info_push` message. By monitoring this push, the payload obtains flight platform context without initiating a request.

The payload can decide whether to enable specific functions based on the aircraft model (`aircraft_type`), and can also return the corresponding widget configuration file according to the mobile App language (`language`) and screen type (`screen_type`).

:::tip Note:
- The C interfaces in PSDK encapsulate the underlying MQTT protocol. Developers can complete protocol interactions by calling the C interfaces directly, without manually constructing MQTT messages. For MQTT payload structures and field definitions, see <a href="../api-reference/api-aircraft-information.html" target="_blank" rel="noopener noreferrer">Protocol Reference - Aircraft Information</a>.
- Before using this function, the payload device must first complete access and authentication. For details, see <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Basic Concepts

### Monitoring Start/Stop Mechanism

Aircraft information monitoring is registered via `ThingModelClientSession_AddListener()`, without creating a new MQTT connection. After the listener receives a message, it first verifies the message type and performs JSON decoding only when the message type is `aircraft_info_push`, to reduce the impact on the message dispatch process.

The monitoring start/stop status (enabled) takes effect according to the following priority:
1. Environment variable `THING_MODEL_AIRCRAFT_INFO` (`0`/`off`/`false` to disable, any other non-empty value to enable)
2. Compile-time macro `SAMPLE_AIRCRAFT_INFO_DEFAULT` (default `1`, i.e., enabled)
3. Runtime `sample_aircraft_info_set_enabled()` toggle (takes effect on the next call to `sample_aircraft_info_start()`)

:::warning Warning:
The listener callback runs on the background message dispatch thread. Do not unregister the listener or destroy the session inside the callback, otherwise a deadlock will occur due to internal lock contention; nor should you call synchronous interfaces, otherwise the dispatch thread will be blocked until timeout, causing the response of this synchronous call to fail to be dispatched. Time-consuming logic should be handed off to other threads.
:::

## Feature Introduction

:::warning Warning:
The following code is for reference only and demonstrates the call flow and implementation of each feature. Developers can adapt it based on the hardware characteristics and application scenarios of the payload device.
:::

### Start Monitoring

Call `sample_aircraft_info_start()` after establishing the MQTT session to register the listener and subscribe to the aircraft information push. When the monitoring status is disabled, the interface returns `0` and does not register the listener or subscribe to the Topic. This interface can be called repeatedly; repeated calls will not register the listener multiple times. For the corresponding MQTT protocol, see <a href="../api-reference/api-aircraft-information.html#aircraft-info-push-push" target="_blank" rel="noopener noreferrer">aircraft_info_push Push</a>.

```c
ThingModelClientSession_t *s = sample_session_open(&cfg);
if (!s) { /* Handle connection failure */ return -1; }

/* Register aircraft information monitoring; does not subscribe to the Topic when enabled=false */
sample_aircraft_info_start(s);
```

:::tip Note:
`sample_aircraft_info_start()` internally calls `ThingModelClientSession_Subscribe()` to subscribe to `thing/product/{sn}/osd`. When `auto_reconnect` is enabled, it automatically re-subscribes after reconnecting.
:::

### Receive Aircraft Information

After the listener recognizes `aircraft_info_push`, it calls the parsing function `AircraftInfoJson_DecodeAircraftInfoPush()` to parse the JSON payload and obtain the aircraft model, firmware version, App information, and device list.

```c
/* In the session listener callback (refer to the internal implementation of sample_aircraft_info.c) */
static void on_session_msg(void *user, const char *topic,
                           const char *payload, size_t len)
{
    /* Only handle the channel used by the aircraft information push */
    if (!strstr(topic, "osd"))                                 return;
    /* Decode only when the target message is received */
    if (!payload_contains(payload, len, "aircraft_info_push")) return;

    T_AircraftInfoPush a;
    AircraftInfo_InitAircraftInfoPush(&a);
    if (AircraftInfoJson_DecodeAircraftInfoPush(payload, &a) == THING_MODEL_RC_OK) {
        printf("[aircraft_info] model=%d firmware=%s App{lang=%d screen=%d} devices=%zu\n",
               a.aircraft_type,
               a.aircraft_version ? a.aircraft_version : "-",
               a.mobile_app_info.language,
               a.mobile_app_info.screen_type,
               a.devices_info_count);

        for (size_t i = 0; i < a.devices_info_count; i++) {
            const T_AircraftDeviceInfo *d = &a.devices_info[i];
            printf("[aircraft_info]   dev[%zu]: id=%s name=%s sn=%s fw=%s type=%d\n",
                   i,
                   d->device_id        ? d->device_id        : "-",
                   d->device_name      ? d->device_name      : "-",
                   d->serial_number    ? d->serial_number    : "-",
                   d->firmware_version ? d->firmware_version : "-",
                   d->device_type);
        }
    }
    AircraftInfo_FreeAircraftInfoPush(&a);
}
```

:::tip Note:
You can pass in the entire payload; the decoder `AircraftInfoJson_DecodeAircraftInfoPush()` reads the outer `data` field. After decoding is complete, you must call `AircraftInfo_FreeAircraftInfoPush()` to release the dynamically allocated string fields (`aircraft_version`, `device_id`, etc.).
:::

Field descriptions of the push data structure `T_AircraftInfoPush`:

| Field | Type | Description |
|---|---|---|
| aircraft_type | int32_t | Aircraft model code (raw integer, to accommodate future new values) |
| aircraft_version | char * | Aircraft firmware version string, such as "01.02.03.04" |
| mobile_app_info | T_MobileAppInfo | Mobile App information, see the table below |
| devices_info | T_AircraftDeviceInfo * | Onboard device list (dynamic array) |
| devices_info_count | size_t | Number of elements in the device list |

Field descriptions of the App information structure `T_MobileAppInfo`:

| Field | Type | Description |
|---|---|---|
| language | int32_t | App system language.<ul><li>0: English</li><li>1: Simplified Chinese</li><li>2: Japanese</li><li>3: French</li></ul> |
| screen_type | int32_t | App screen type.<ul><li>0: Large screen</li><li>1: Small screen</li></ul> |

Field descriptions of the device information structure `T_AircraftDeviceInfo`:

| Field | Type | Description |
|---|---|---|
| device_id | char * | Device ID, such as &lt;client_id&gt; |
| device_name | char * | Device name |
| serial_number | char * | Serial number |
| firmware_version | char * | Firmware version string |
| device_type | int32_t | Device category.<ul><li>1: Aircraft</li><li>4: Payload</li></ul> |

### Toggle Monitoring Status

During runtime, you can use `sample_aircraft_info_set_enabled()` to disable or re-enable aircraft information monitoring. The setting takes effect on the next call to `sample_aircraft_info_start()`.

```c
/* Disable aircraft information monitoring (e.g., when the current service does not need aircraft information) */
sample_aircraft_info_set_enabled(false);

/* Query the monitoring start/stop status */
if (sample_aircraft_info_enabled()) {
    printf("[aircraft_info] Aircraft information monitoring is enabled\n");
}

/* Query whether a push has been received */
if (sample_aircraft_info_got_push()) {
    printf("[aircraft_info] Aircraft information obtained\n");
}
```

### Stop Monitoring

When aircraft information is no longer needed, call `sample_aircraft_info_stop()` to unregister the listener.

```c
sample_aircraft_info_stop();
sample_session_close(s);
```
