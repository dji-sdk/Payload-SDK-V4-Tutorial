## Overview

Data Subscription is used to obtain aircraft telemetry data on demand, covering topics such as attitude, velocity, position, GPS, RTK, remote controller, flight status, gimbal, obstacle avoidance, and battery.

The payload can subscribe to a topic, unsubscribe, or query the latest value; after a successful subscription, the flight controller pushes data through the osd channel at the set frequency, and different topics are reported with different messages.

:::tip Note:
- The C interfaces in PSDK encapsulate the underlying MQTT protocol. Developers can complete protocol interactions by calling the C interfaces directly, without manually constructing MQTT messages. For MQTT payload structures and field definitions, see <a href="../api-reference/api-fc-subscription.html" target="_blank" rel="noopener noreferrer">Protocol Reference - Data Subscription</a>.
- Before using this function, the payload device must first complete access and authentication. For details, see <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Basic Concepts

### Terminology

**topic**

The identifier of a category of telemetry data that the flight controller can subscribe to, such as `quaternion`, `velocity`, `battery_single_info_index1` (details of battery 1). Each topic corresponds to a fixed set of fields. For all topics, see [Subscription Topic List](#subscription-topic-list).

**frequency**

The frequency at which the flight controller pushes data for a topic, in Hz. Options are 1 / 5 / 10 / 50 Hz. Calling the subscription interface repeatedly for the same topic can update the frequency, and the new frequency overrides the old subscription.

**osd push**

The channel through which the flight controller pushes subscription data to the payload. The flight controller pushes data at the subscription frequency of each topic, and data of different topics is pushed separately through different messages. The payload receives these push messages by subscribing to the osd channel.

### Relationship Between Subscription Frequency and Push

The push of data subscription is determined jointly by the subscription status and frequency:

1. The payload calls `DataSubscription_SubscribeTopic()` to subscribe to a topic and set the frequency.
2. The flight controller pushes the topic data at that frequency, and the payload receives it from the osd channel.
3. The payload calls `DataSubscription_UnsubscribeTopic()` to unsubscribe, and the flight controller stops pushing the topic.

:::warning Warning:
When subscribing to multiple topics in batches, send them in batches and leave intervals between requests to avoid a large number of requests piling up in a short time, which may cause subscription failures or timeouts. The processing of received data should be performed on a background thread, and the processing logic should not call the data subscription API or destroy the client; time-consuming logic should be handed off to other threads.
:::

### Subscription Topic List

Data subscription supports multiple categories of telemetry topics such as attitude, position, velocity, GPS, RTK, remote controller, flight status, gimbal, obstacle avoidance, and battery. For the `topic` values, recommended subscription frequencies, and data field structures of each topic, see the protocol documents <a href="../api-reference/api-fc-subscription.html#subscription-topic-list" target="_blank" rel="noopener noreferrer">Subscription Topic List</a> and <a href="../api-reference/api-fc-subscription.html#flight-control-data-push" target="_blank" rel="noopener noreferrer">Flight Control Data Push</a>.

:::tip Note:
The topics supported by different aircraft models may vary. If the subscription interface returns success but a topic has no push data for a long time, it usually indicates that the current aircraft model does not support the topic. The frequencies in the table are recommended values; the actually supported frequencies depend on the specific topic.
:::

## Feature Introduction

:::warning Warning:
The following code is for reference only and demonstrates the call flow and implementation of each feature. Developers can adapt it based on the hardware characteristics and application scenarios of the payload device.
:::

### Create Client

Create a data subscription client on the established MQTT session `s`. Subsequent interfaces are all called through this client.

```c
DataSubscription_Client_t *ds = DataSubscription_CreateClient(s);
```

### Receive Push Data

The payload subscribes to the osd channel to receive the subscription data pushed by the flight controller. The flight controller pushes data at the subscription frequency, and data of different topics is pushed separately through different messages. The payload parses the fields of the corresponding topic during message processing. For the corresponding MQTT protocol, see <a href="../api-reference/api-fc-subscription.html#flight-control-data-push" target="_blank" rel="noopener noreferrer">Flight Control Data Push</a>.

```c
static void on_publish_data(void *user, const T_DataSubscriptionPublishDataPush *p)
{
    if (!p) return;
    /* In p, only the fields of subscribed topics are filled; unsubscribed topics remain zero-valued */
    USER_LOG_INFO("quaternion: q0=%.4f q1=%.4f q2=%.4f q3=%.4f",
                  p->quaternion.q0, p->quaternion.q1,
                  p->quaternion.q2, p->quaternion.q3);
    USER_LOG_INFO("velocity: x=%.3f y=%.3f z=%.3f health=%d",
                  p->velocity.x, p->velocity.y, p->velocity.z, p->velocity.health);
}

T_ThingModelReturnCode rc = DataSubscription_OnPublishData(ds, on_publish_data, NULL);
if (rc != THING_MODEL_RC_OK) {
    USER_LOG_ERROR("register publish data callback failed: rc=%d", rc);
}
```

:::warning Warning:
The processing of received data is performed on a background thread, and the processing logic should not call the data subscription API or destroy the client; time-consuming logic should be handed off to other threads.
:::

### Subscribe to a Topic

Subscribe to a specified topic and set the flight controller push frequency. After a successful subscription, the flight controller starts pushing the topic data at the `frequency`. Calling repeatedly for the same topic can update the frequency. For the corresponding MQTT protocol, see <a href="../api-reference/api-fc-subscription.html#subscribe-to-a-topic" target="_blank" rel="noopener noreferrer">Subscribe to a Topic</a>.

```c
T_DataSubscriptionSubscribeTopicRequest req;
DataSubscription_InitDataSubscriptionSubscribeTopicRequest(&req);
req.topic     = "quaternion";
req.frequency = DATA_SUBSCRIPTION_FREQUENCY_10HZ;

T_ThingModelCommonReply resp = {0};
T_ThingModelReturnCode rc = DataSubscription_SubscribeTopic(ds, &req, &resp, 5000);
if (rc == THING_MODEL_RC_OK && resp.result == 0) {
    USER_LOG_INFO("subscribe quaternion 10Hz success.");
} else {
    USER_LOG_ERROR("subscribe topic failed: rc=%d result=%d msg=%s",
                   rc, resp.result, resp.result_message);
}
```

Values of the subscription frequency enum `E_DataSubscriptionFrequency`:

| Enum Constant | Value | Meaning |
|------|------|------|
| DATA_SUBSCRIPTION_FREQUENCY_1HZ | 1 | 1 Hz |
| DATA_SUBSCRIPTION_FREQUENCY_5HZ | 5 | 5 Hz |
| DATA_SUBSCRIPTION_FREQUENCY_10HZ | 10 | 10 Hz |
| DATA_SUBSCRIPTION_FREQUENCY_50HZ | 50 | 50 Hz |

:::tip Note:
Before calling, first initialize the request structure with `DataSubscription_InitDataSubscriptionSubscribeTopicRequest()`, then set the `topic` and `frequency` fields. When subscribing to multiple topics in batches, send them in batches and add intervals between requests to avoid a large number of requests piling up in a short time, which may cause subscription failures or timeouts.
:::

### Unsubscribe

Unsubscribe from a specified topic, and the flight controller stops pushing the topic data. For the corresponding MQTT protocol, see <a href="../api-reference/api-fc-subscription.html#unsubscribe" target="_blank" rel="noopener noreferrer">Unsubscribe</a>.

```c
T_DataSubscriptionUnsubscribeTopicRequest req;
DataSubscription_InitDataSubscriptionUnsubscribeTopicRequest(&req);
req.topic = "quaternion";

T_ThingModelCommonReply resp = {0};
T_ThingModelReturnCode rc = DataSubscription_UnsubscribeTopic(ds, &req, &resp, 5000);
if (rc == THING_MODEL_RC_OK && resp.result == 0) {
    USER_LOG_INFO("unsubscribe quaternion success.");
} else {
    USER_LOG_ERROR("unsubscribe topic failed: rc=%d result=%d msg=%s",
                   rc, resp.result, resp.result_message);
}
```

### Query the Latest Value

Query the latest data of a specified topic in a one-time manner. The target topic must be subscribed before querying. For the corresponding MQTT protocol, see <a href="../api-reference/api-fc-subscription.html#query-the-latest-value" target="_blank" rel="noopener noreferrer">Query the Latest Value</a>.

```c
T_DataSubscriptionGetLatestValueRequest req;
DataSubscription_InitDataSubscriptionGetLatestValueRequest(&req);
req.topic = "quaternion";

T_ThingModelCommonReply resp = {0};
T_ThingModelReturnCode rc = DataSubscription_GetLatestValue(ds, &req, &resp, 5000);
if (rc == THING_MODEL_RC_OK && resp.result == 0) {
    USER_LOG_INFO("get latest value of quaternion request accepted.");
} else {
    USER_LOG_ERROR("get latest value failed: rc=%d result=%d msg=%s",
                   rc, resp.result, resp.result_message);
}
```

:::tip Note:
The query result is returned by `DataSubscription_GetLatestValue()`, and the payload reads the data of the corresponding topic from `resp`.
:::

### Destroy Client

When the data subscription function is no longer used, destroy the client to release resources. Before destroying, unsubscribe from the subscribed topics first.

```c
DataSubscription_DestroyClient(ds);
```
