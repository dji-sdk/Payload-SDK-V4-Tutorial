## Overview

:::warning Warning:
The PPS signal source for time synchronization has a mutual exclusion constraint with other features based on the PPS signal. For the Matrice 5TD model, the PPS signal cannot be used simultaneously with features based on PWM/PPS such as EFTS; if EFTS is already enabled, you must first disable it and re-plug the payload before switching to PPS time synchronization.
:::

Time synchronization is used to keep the payload and the flight platform on a consistent time reference. The payload can select the time synchronization signal source: FTS signal (default) or PPS signal. When the signal source is PPS, the aircraft periodically pushes the UTC time to the payload, and the payload calibrates its local clock accordingly.

:::tip Note:
- The C interfaces in PSDK encapsulate the underlying MQTT protocol. Developers can complete protocol interactions by calling the C interfaces directly, without manually constructing MQTT messages. For MQTT payload structures and field definitions, see <a href="../api-reference/api-time-sync.html" target="_blank" rel="noopener noreferrer">Protocol Reference - Time Synchronization</a>.
- Before using this feature, the payload device must first complete access and authentication. For details, see <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Basic Concepts

### Terminology

**FTS Signal**

The default signal source for time synchronization. This pin is the same physical pin as the FTS trigger pin of <a href="eu-c6.html" target="_blank" rel="noopener noreferrer">GEO Caging</a> (pin multiplexing): when in FTS mode, this pin is used for GEO Caging and not for time synchronization, so the aircraft does not push the UTC time. When time synchronization is needed, the signal mode should be switched to PPS.

**PPS Signal (PPS, Pulse Per Second)**

Pulse per second signal. After switching the time synchronization signal source to PPS, the aircraft periodically pushes the UTC time to the payload, used to align the payload's local clock with the flight platform.

### Relationship Between Signal Mode and UTC Reporting

The UTC time reporting for time synchronization is determined by the signal mode:

1. The payload calls `TimeSync_SetSignalMode()` to set the mode to PPS.
2. The aircraft begins periodically pushing the UTC time through the `time_sync` event, and the payload receives it in the registered callback.

:::warning Warning:
The callback is triggered on a background thread. Within the callback, you should not call time synchronization APIs or destroy the client; time-consuming operations should be handed off to other threads for processing.
:::

## Feature Introduction

:::warning Warning:
The following code is for reference only and demonstrates the call flow and implementation of each feature. Developers can adapt it based on the hardware characteristics and application scenarios of the payload device.
:::

### Create Client

Create a time synchronization client on the established MQTT session `s`. Subsequent interfaces are all called through this client.

```c
TimeSync_Client_t *ts = TimeSync_CreateClient(s);
```

### Receive UTC Time

Register a callback to receive the UTC time pushed by the aircraft. The callback is triggered periodically when the signal mode is PPS, and the parameter `p` points to the decoded UTC time structure. You should register the callback first and then switch to PPS mode, to avoid missing early reports. For the corresponding MQTT protocol, see <a href="../api-reference/api-time-sync.html#receive-utc-time" target="_blank" rel="noopener noreferrer">Receive UTC Time</a>.

```c
static void on_time_sync(void *user, const T_TimeSyncTimeSyncPush *p)
{
    if (!p) return;
    USER_LOG_INFO("UTC %04d-%02d-%02d %02d:%02d:%02d.%09d",
                  p->year, p->month, p->day,
                  p->hour, p->minute, p->second, p->nano_second);
}

T_ThingModelReturnCode rc = TimeSync_OnSync(ts, on_time_sync, NULL);
if (rc != THING_MODEL_RC_OK) {
    USER_LOG_ERROR("subscribe time_sync failed: rc=%d", rc);
}
```

Field descriptions of the push structure `T_TimeSyncTimeSyncPush`:

| Field | Type | Description |
|------|------|------|
| year | int32_t | Year |
| month | int32_t | Month, value 1~12 |
| day | int32_t | Day, value 1~31 |
| hour | int32_t | Hour, value 0~23 |
| minute | int32_t | Minute, value 0~59 |
| second | int32_t | Second, value 0~59 |
| nano_second | int32_t | Nanosecond, value 0~999999999 |

### Set Time Synchronization Signal Mode

Set the time synchronization signal source. Passing in `TIME_SYNC_SIGNAL_MODE_PPS` to switch to PPS makes the aircraft begin pushing the UTC time; passing in `TIME_SYNC_SIGNAL_MODE_FTS` to revert to the default stops the pushing. For the corresponding MQTT protocol, see <a href="../api-reference/api-time-sync.html#set-time-synchronization-signal-mode" target="_blank" rel="noopener noreferrer">Set Time Synchronization Signal Mode</a>.

```c
T_TimeSyncSetSignalModeRequest req;
TimeSync_InitTimeSyncSetSignalModeRequest(&req);
req.mode = TIME_SYNC_SIGNAL_MODE_PPS;

T_ThingModelCommonReply resp = {0};
T_ThingModelReturnCode rc = TimeSync_SetSignalMode(ts, &req, &resp, 5000);
if (rc == THING_MODEL_RC_OK && resp.result == 0) {
    USER_LOG_INFO("set signal mode PPS success.");
} else {
    USER_LOG_ERROR("set signal mode failed: rc=%d result=%d msg=%s",
                   rc, resp.result, resp.result_message);
}
```

Values of the signal mode enumeration `E_TimeSyncSignalMode`:

| Enumeration Constant | Value | Meaning |
|------|------|------|
| TIME_SYNC_SIGNAL_MODE_FTS | 0 | FTS signal (default) |
| TIME_SYNC_SIGNAL_MODE_PPS | 1 | PPS signal |

:::tip Note:
Before calling, you should first initialize the request structure with `TimeSync_InitTimeSyncSetSignalModeRequest()`, and then set the `mode` field.
:::

### Destroy Client

When the time synchronization feature is no longer used, destroy the client to release resources.

```c
TimeSync_DestroyClient(ts);
```
