## Overview

Power management is used to coordinate the power supply state between the payload and the aircraft, and provides the power-off notification interface.

Before powering off, the aircraft sends a power-off notification to the payload, and the payload returns in its response whether it is ready to power off.

:::tip Note:
- The C interfaces in PSDK encapsulate the underlying MQTT protocol. Developers can complete protocol interactions by calling the C interfaces directly, without manually constructing MQTT messages. For MQTT payload structures and field definitions, see <a href="../api-reference/api-power-management.html" target="_blank" rel="noopener noreferrer">Protocol Reference - Power Management</a>.
- Before using this feature, the payload device must first complete access and authentication. For details, see <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Basic Concepts

### Terminology

**Power-off Notification**

A notification issued by the aircraft to the payload before powering off. After receiving it, the payload should complete finishing operations such as saving data and powering off peripherals, and inform the aircraft via `preparation_flag` in the response whether it is ready to power off.

**Power-off Notification Responder**

The payload-side object used to receive and respond to power-off notifications issued by the aircraft. The payload registers a handler callback, and the SDK invokes this callback when the aircraft issues a power-off notification.

## Feature Introduction

:::warning Warning:
The following code is for reference only and demonstrates the call flow and implementation of each feature. Developers can adapt it based on the hardware characteristics and application scenarios of the payload device.
:::

### Create Responder

Create the power-off notification responder on the established MQTT session `s` to register the power-off notification callback.

```c
PowerImpl_t *impl = PowerImpl_Create(s, device_sn);
```

### Respond to Power-off Notification

Register the `Power-off Notification` callback. When the aircraft issues a power-off notification, the payload completes the finishing operations before powering off in the callback, and returns whether it is ready to power off via `preparation_flag`. For the corresponding MQTT protocol, see <a href="../api-reference/api-power-management.html#power-off-notification" target="_blank" rel="noopener noreferrer">Power-off Notification</a>.

```c
static T_ThingModelReturnCode on_power_off(PowerImpl_t *impl, void *user,
                                           const T_Placeholder *req,
                                           T_PowerOffNotificationReply *reply)
{
    reply->result           = 0;
    reply->result_message   = strdup("success");
    reply->preparation_flag = true;   /* Ready to power off */
    return THING_MODEL_RC_OK;
}

PowerImpl_OnPowerOffNotification(impl, on_power_off, NULL);
```

:::tip Note:
The `result_message` of `T_PowerOffNotificationReply` is a `char *`. The SDK releases it after replying, so it must be heap-allocated using methods such as `strdup`; string literals or stack addresses cannot be used. The callback is triggered on a background thread. Power management APIs should not be called within the callback, nor should the responder be destroyed within it; time-consuming operations should be handed off to other threads.
:::

Field descriptions of the reply structure `T_PowerOffNotificationReply`:

| Field | Type | Description |
|------|------|------|
| result | int32_t | Processing result, 0 indicates success |
| result_message | char * | Result description information |
| preparation_flag | bool | Whether ready to power off.<ul><li>false: Not ready</li><li>true: Ready</li></ul> |

### Destroy Responder

When the power management feature is no longer used, destroy the responder to release resources.

```c
PowerImpl_Destroy(impl);
```
