## Overview

The custom widget feature is used to display payload-defined interactive widgets and floating window information on the aircraft app, such as buttons, switches, sliders, lists, and integer input boxes.

The aircraft can read the widget configuration and set or read widget values. The payload registers callbacks to handle these commands and actively reports widget status and floating window messages. Widget configuration files are transferred through the payload-side HTTP service.

:::tip Note:
- The C interfaces in PSDK encapsulate the underlying MQTT protocol. Developers can complete protocol interactions by calling the C interfaces directly, without manually constructing MQTT messages. For MQTT payload structures and field definitions, see <a href="../api-reference/api-custom-widget.html" target="_blank" rel="noopener noreferrer">Protocol Reference - Custom Widget</a>.
- Before using this feature, the payload device must first complete access and authentication. For details, see <a href="access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Basic Concepts

### Terminology

**Widget Command Responder**

The payload-side object used to receive and respond to the three widget commands issued by the aircraft. The payload registers a handler callback for each command, and the SDK invokes the corresponding callback when the aircraft issues the command.

**Widget Status Publisher**

The payload-side object used to actively report widget status and floating window messages to the aircraft. The payload periodically publishes the widget status list and floating window text through this object.

**Widget Types**

The types supported by custom widgets: Button, Switch, Scale, List, and IntInputBox. The layout and initial values of widgets are defined by the widget configuration file (`widget_config.json`).

### Widget Configuration File

The widget layout is defined in the configuration file. The aircraft first obtains the file list, including `md5`, through the `Get Widget File List` interface, and then downloads the file content through the payload-side HTTP service. The payload returns the matching configuration file list based on the app language and screen type.

## Feature Introduction

:::warning Warning:
The following code is for reference only and demonstrates the call flow and implementation of each feature. Developers can adapt it based on the hardware characteristics and application scenarios of the payload device.
:::

### Create Responder and Publisher

Create the widget command responder and status publisher on the established MQTT session `s`. Subsequent command callbacks are registered through the responder, and widget status and floating window messages are published through the publisher.

```c
WidgetImpl_t *wimpl = WidgetImpl_Create(s, device_sn);
Widget_Publisher_t *wpub = Widget_CreatePublisher(s);
```

### Get Widget File List

Register the `Get Widget File List` callback. When the aircraft issues this command, the payload returns the widget configuration file list according to the requested language and screen type in the callback. For the corresponding MQTT protocol, see <a href="../api-reference/api-custom-widget.html#get-widget-file-list" target="_blank" rel="noopener noreferrer">Get Widget File List</a>.

```c
static T_ThingModelReturnCode on_get_file_list(WidgetImpl_t *impl, void *user,
        const T_WidgetGetFileListRequest *req, T_WidgetGetFileListReply *reply)
{
    E_AppLanguage lang = req ? req->language : APP_LANGUAGE_ENGLISH;

    T_WidgetFileInfo *arr = ThingModelMem_Calloc(1, sizeof(*arr));
    arr[0].file_index = 0;
    arr[0].file_name  = ThingModelMem_Strdup("widget_config.json");
    arr[0].file_size  = 2048;
    arr[0].md5        = ThingModelMem_Strdup("9e107d9d372bb6826bd81d3542a419d6");

    reply->result          = 0;
    reply->result_message  = ThingModelMem_Strdup("success");
    reply->file_list       = arr;
    reply->file_list_count = 1;
    return THING_MODEL_RC_OK;
}

WidgetImpl_OnGetFileList(wimpl, on_get_file_list, NULL);
```

:::tip Note:
The `result_message` of `T_WidgetGetFileListReply` and the `file_name` and `md5` of the file items are all `char *`. The SDK releases them after sending the reply, so they must be heap-allocated using methods such as `ThingModelMem_Strdup`; the `file_list` array is allocated with `ThingModelMem_Calloc`, and `file_list_count` should be filled with the actual number of files.
:::

Field descriptions of the request structure `T_WidgetGetFileListRequest`:

| Field | Type | Description |
|------|------|------|
| language | E_AppLanguage | APP system language.<ul><li>APP_LANGUAGE_ENGLISH (0): English</li><li>APP_LANGUAGE_CHINESE_SIMPLIFIED (1): Simplified Chinese</li><li>APP_LANGUAGE_JAPANESE (2): Japanese</li><li>APP_LANGUAGE_FRENCH (3): French</li></ul> |
| screen_type | E_ScreenType | APP screen type.<ul><li>SCREEN_TYPE_LARGE (0): large screen</li><li>SCREEN_TYPE_SMALL (1): small screen</li></ul> |

Field descriptions of the reply structure `T_WidgetGetFileListReply`:

| Field | Type | Description |
|------|------|------|
| result | int32_t | Processing result, 0 indicates success |
| result_message | char * | Result description information |
| file_list | T_WidgetFileInfo * | Widget configuration file list |
| file_list_count | size_t | Number of elements in the file list |

Field descriptions of the file item structure `T_WidgetFileInfo`:

| Field | Type | Description |
|------|------|------|
| file_index | int32_t | File index |
| file_name | char * | File name, such as `widget_config.json` |
| file_size | int32_t | File size, in bytes |
| md5 | char * | File MD5, used for verification and to determine whether an update is needed |

### Set Widget Value

Register the `Set Widget Value` callback. When the aircraft issues this command, the payload updates the value of the corresponding widget and returns the result in the callback. For the corresponding MQTT protocol, see <a href="../api-reference/api-custom-widget.html#set-widget-value" target="_blank" rel="noopener noreferrer">Set Widget Value</a>.

```c
static T_ThingModelReturnCode on_set_value(WidgetImpl_t *impl, void *user,
        const T_WidgetSetValueRequest *req, T_ThingModelCommonReply *reply)
{
    apply_widget_value(req->widget_index, req->widget_type, req->widget_value);
    reply->result = 0;
    snprintf(reply->result_message, sizeof(reply->result_message), "success");
    return THING_MODEL_RC_OK;
}

WidgetImpl_OnSetValue(wimpl, on_set_value, NULL);
```

:::tip Note:
The `result_message` of `T_ThingModelCommonReply` is a fixed-length character array and should be filled using `snprintf`, not `strdup`.
:::

Field descriptions of the request structure `T_WidgetSetValueRequest`:

| Field | Type | Description |
|------|------|------|
| widget_index | int32_t | Widget index |
| widget_type | int32_t | Widget type.<ul><li>1: Button</li><li>2: Switch</li><li>3: Scale</li><li>4: List</li><li>5: IntInputBox</li></ul> |
| widget_value | int32_t | Widget value |

### Get Widget Value

Register the `Get Widget Value` callback. When the aircraft issues this command, the payload echoes the widget index and returns the current value in the callback. For the corresponding MQTT protocol, see <a href="../api-reference/api-custom-widget.html#get-widget-value" target="_blank" rel="noopener noreferrer">Get Widget Value</a>.

```c
static T_ThingModelReturnCode on_get_value(WidgetImpl_t *impl, void *user,
        const T_WidgetGetValueRequest *req, T_WidgetGetValueReply *reply)
{
    reply->result         = 0;
    reply->result_message = ThingModelMem_Strdup("success");
    reply->widget_index   = req->widget_index;
    reply->widget_value   = query_widget_value(req->widget_index);
    return THING_MODEL_RC_OK;
}

WidgetImpl_OnGetValue(wimpl, on_get_value, NULL);
```

:::tip Note:
The `result_message` of `T_WidgetGetValueReply` is a `char *`. The SDK releases it after sending the reply, so it must be heap-allocated using methods such as `ThingModelMem_Strdup`.
:::

Field descriptions of the reply structure `T_WidgetGetValueReply`:

| Field | Type | Description |
|------|------|------|
| result | int32_t | Processing result, 0 indicates success |
| result_message | char * | Result description information |
| widget_index | int32_t | Widget index (echoes the index in the request) |
| widget_value | int32_t | Current widget value |

### Widget State Push

Use the publisher to report the current status of all widgets to the aircraft. After constructing the widget status list, call the publish interface. For the corresponding MQTT protocol, see <a href="../api-reference/api-custom-widget.html#widget-state-push" target="_blank" rel="noopener noreferrer">Widget State Push</a>.

```c
T_WidgetStateItem items[1] = {
    { .widget_index = 2, .widget_type = (char *)"switch", .widget_value = 1 },
};
T_WidgetStatePush push = { .widget_list = items, .widget_list_count = 1 };
Widget_PublishState(wpub, &push);
```

Field descriptions of the push structure `T_WidgetStatePush`:

| Field | Type | Description |
|------|------|------|
| widget_list | T_WidgetStateItem * | Widget status list |
| widget_list_count | size_t | Number of elements in the widget status list |

Field descriptions of the status item structure `T_WidgetStateItem`:

| Field | Type | Description |
|------|------|------|
| widget_index | int32_t | Widget index |
| widget_type | char * | Widget type.<ul><li>button</li><li>list</li><li>switch</li><li>scale</li><li>int_input_box</li></ul> |
| widget_value | int32_t | Current widget value |

### Float Window Message Push

Use the publisher to report the text displayed in the floating window to the aircraft. For the corresponding MQTT protocol, see <a href="../api-reference/api-custom-widget.html#float-window-message-push" target="_blank" rel="noopener noreferrer">Float Window Message Push</a>.

```c
T_WidgetFloatWindowPush fw = { .message = (char *)"payload status: OK" };
Widget_PublishFloatWindowMsg(wpub, &fw);
```

Field descriptions of the push structure `T_WidgetFloatWindowPush`:

| Field | Type | Description |
|------|------|------|
| message | char * | Message text displayed in the floating window |

### Destroy Responder and Publisher

When the custom widget feature is no longer used, destroy the responder and publisher to release resources.

```c
WidgetImpl_Destroy(wimpl);
Widget_DestroyPublisher(wpub);
```
