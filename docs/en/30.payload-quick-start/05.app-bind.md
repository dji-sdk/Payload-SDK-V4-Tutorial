## Overview

Application binding (Bind) is used to establish an **identity authorization relationship between the payload device and the flight platform**. After the payload device connects to the MQTT broker, the aircraft will only allow business requests once binding is completed and authorization is obtained.

The binding action is performed by the pilot through DJI Assistant 2. After binding is completed, when the payload device is mounted on the drone, the payload device will automatically run the sample program compiled or flashed by the developer.

:::warning Warning:
Application binding is a prerequisite for business functions. When the device is unbound, the aircraft will reject business requests; after the payload comes online, you should first confirm the binding status before starting business functions such as widgets and speakers.
:::

## Whether Application Binding Is Required

Whether application binding is required depends on the payload's **access method**: binding is required when connecting via a method **with an authentication chip** (such as the E-Port V3 coaxial cable, SkyPort, and other adapter rings); direct-connect payloads that do not use an authentication chip (such as Manifold 3) do not require binding. The currently supported access methods are as follows (this will continue to be updated as new models / development kits are added):

## Application Binding Operation Procedure

:::tip Note:
* When binding or debugging a payload device with DJI Assistant 2, first turn on the **"Data Authorization"** switch in the "Configuration" tab at the top-right corner of the software; otherwise DJI Assistant 2 will not be able to bind or debug the payload device properly.
* Application binding is only required for the first use on a drone. No re-binding is needed for subsequent use on different drones.
:::

1. Mount the payload device development board (such as GD32F527ZMT7) on the DJI drone, and connect the DJI drone to the computer.
2. Log in to DJI Assistant 2 using the **account** in the **application information**, click the "Payload SDK" tab, and enter the PSDK hardware platform interface.
3. On the PSDK hardware platform interface, click the "Bind" button to bind the hardware platform, sample program, and DJI drone.
4. After binding succeeds, the binding status on the PSDK hardware platform interface will show `Bound`, as shown in the figure below.

5. After application binding succeeds, the payload device will be allowed to use PSDK functions.

## Confirmation Before Running the Demo

After completing the above binding, confirm the following before running the Demo:

1. The payload device has successfully connected to the broker through authentication.
2. The pilot has completed device binding through DJI Assistant 2.
3. The Demo program monitors the binding status and starts business functions only after confirming that `bind_state` is bound.

For the usage of the C interfaces for binding status monitoring and querying, along with code examples, see <a href="../function-set/bind.html" target="_blank" rel="noopener noreferrer">Function Set - Binding Status Notification</a>. For the underlying MQTT protocol, see <a href="../api-reference/api-bind.html" target="_blank" rel="noopener noreferrer">Protocol Reference - Binding Status Notification</a>.
