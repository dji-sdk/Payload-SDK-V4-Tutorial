This section defines the MQTT interfaces of the EFTS (Emergency Flight Termination System) feature, covering the MQTT payload structures and field descriptions for enabling the payload PWM trigger port and querying the FTS PWM trigger status.

:::tip Note:
- The C interfaces in PSDK encapsulate the MQTT protocol described in this section. When developing with PSDK, you do not need to handle MQTT messages directly. Refer to these protocol definitions only if you need to implement the protocol yourself or debug and verify the underlying messages. For the feature overview and C interface examples, see <a href="../function-set/eu-c6.html" target="_blank" rel="noopener noreferrer">Function Set - GEO Caging</a>.
- Before using this feature, the payload device must first complete access and authentication. For the access protocol, see <a href="api-access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Protocol Description

The Topics involved in the interfaces are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| service request | payload → aircraft | thing/product/{client_id}/services |
| service response | aircraft → payload | thing/product/{client_id}/services_reply |

- `{client_id}` is the payload device serial number.
- **QoS**: 0.

The interfaces supported by this module are as follows:

| method | Type | Purpose | Corresponding C interface |
|:---|:---|:---|:---|
| efts_select_pwm_trigger | service | Enable the payload-side PWM trigger port | Efts_SelectFtsPwmTrigger() |
| efts_get_trigger_status | service | Query the FTS PWM trigger status | Efts_GetFtsTriggerStatus() |

## Common Parameters

The following parameters are the top-level common parameters shared by the requests and responses of all EFTS interfaces, and are not repeated in the field descriptions of each interface.

### Request Parameters

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| seq | integer | Yes | Request sequence number; echoed back unchanged in the response, used to match request and response. |
| method | string | Yes | Method identifier; for values, see each interface description. |
| data | object | Yes | Service data body; `{}` when there are no service parameters. |

### Response Parameters

The top-level fields of the response are the same as the request. `data` includes the following common fields by default; for interface-specific fields, see the corresponding section.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| result | integer | Yes | Processing result.<ul><li>0: Success</li><li>Non-zero: Failure</li></ul> |
| result_message | string | Yes | Result description message. |

## Enable FTS PWM Trigger Port

Enable the payload-side PWM trigger port. This interface only enables the trigger port; it does not output a PWM signal, nor does it perform a propeller stop action. After enabling, external PWM hardware outputs a spec-compliant PWM signal to the port, triggering the flight platform to stop the propellers. This interface should be called when the aircraft is on the ground (already landed).

Related feature section: <a href="../function-set/eu-c6.html#enable-fts-pwm-trigger-port" target="_blank" rel="noopener noreferrer">Enable FTS PWM Trigger Port</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: payload → aircraft
- **QoS**: 0
- **method**: `efts_select_pwm_trigger`
- **Corresponding interface**: `Efts_SelectFtsPwmTrigger()`

```json
{
  "seq": 1,
  "method": "efts_select_pwm_trigger",
  "data": {}
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters); `data` is a fixed empty object `{}`.

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: aircraft → payload

```json
{
  "seq": 1,
  "method": "efts_select_pwm_trigger",
  "data": {
    "result": 0,
    "result_message": "success"
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters); there are no interface-specific fields in `data`.

## Query FTS PWM Trigger Status

Query the current FTS PWM trigger status and the cumulative number of correctly received PWM propeller stop signals. If you need to confirm the propeller stop execution effect, you can also subscribe to the flight control ESC data and verify via the ESC rotation speed.

Related feature section: <a href="../function-set/eu-c6.html#query-fts-pwm-trigger-status" target="_blank" rel="noopener noreferrer">Query FTS PWM Trigger Status</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: payload → aircraft
- **QoS**: 0
- **method**: `efts_get_trigger_status`
- **Corresponding interface**: `Efts_GetFtsTriggerStatus()`

```json
{
  "seq": 2,
  "method": "efts_get_trigger_status",
  "data": {}
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters); `data` is a fixed empty object `{}`.

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: aircraft → payload

```json
{
  "seq": 2,
  "method": "efts_get_trigger_status",
  "data": {
    "result": 0,
    "result_message": "success",
    "fts_status": 1,
    "fts_pwm_cnt": 5
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters); the `data` field description is as follows:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| fts_status | integer | Yes | FTS PWM trigger status.<ul><li>0: Not triggered</li><li>1: Triggered</li></ul> |
| fts_pwm_cnt | integer | Yes | The cumulative number of correctly received PWM propeller stop signals. |
