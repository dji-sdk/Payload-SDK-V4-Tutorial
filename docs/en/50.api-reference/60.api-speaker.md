This section defines the MQTT interfaces of the speaker  feature, covering the MQTT payload structures and field descriptions for setting the work mode, setting the play mode, setting the volume, starting playback, stopping playback, starting audio transfer, transferring audio data packets, finishing audio transfer, and pushing speaker status.

:::tip Note:
- The C interfaces in PSDK encapsulate the MQTT protocol described in this section. When developing with PSDK, you do not need to handle MQTT messages directly. Refer to these protocol definitions only if you need to implement the protocol yourself or debug and verify the underlying messages. For the feature overview and C interface examples, see <a href="../function-set/speaker.html" target="_blank" rel="noopener noreferrer">Function Set - Speaker Widget</a>.
- Before using this feature, the payload device must first complete access and authentication. For the access protocol, see <a href="api-access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Protocol Description

The Topics involved in the interfaces are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| service request | aircraft → payload | thing/product/{client_id}/services |
| service response | payload → aircraft | thing/product/{client_id}/services_reply |
| state push | payload → aircraft | thing/product/{client_id}/state |

- `{client_id}` is the payload device serial number.
- **QoS**: 0.

The interfaces supported by this module are as follows:

| method | Type | Purpose | Corresponding C interface |
|:---|:---|:---|:---|
| speaker_set_work_mode | service | Aircraft sets the speaker work mode | SpeakerImpl_OnSetWorkMode() |
| speaker_set_play_mode | service | Aircraft sets the speaker play mode | SpeakerImpl_OnSetPlayMode() |
| speaker_set_volume | service | Aircraft sets the speaker volume | SpeakerImpl_OnSetVolume() |
| speaker_start_play | service | Aircraft controls the speaker to start playing | SpeakerImpl_OnStartPlay() |
| speaker_stop_play | service | Aircraft controls the speaker to stop playing | SpeakerImpl_OnStopPlay() |
| speaker_trans_start | service | Aircraft starts transferring an audio file to the payload | SpeakerImpl_OnTransStart() |
| speaker_trans_data | service | Aircraft transfers audio binary data packet by packet | SpeakerImpl_OnTransData() |
| speaker_trans_finish | service | Aircraft finishes audio transfer and verifies | SpeakerImpl_OnTransFinish() |
| speaker_state | state | Payload pushes the speaker state | Speaker_PublishState() |

## Common Parameters

The following parameters are the top-level common parameters shared by the messages of the speaker interfaces, and are not repeated in the field descriptions of each interface.

### Request Parameters

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| seq | integer | Yes | Request sequence number; echoed back unchanged in the response, used to match request and response. |
| method | string | Yes | Method identifier; for values, see each interface description. |
| data | object | Yes | Service data body; an empty object when there are no service parameters. |

### Response Parameters

The top-level fields of the response are the same as the request. `data` includes the following common fields by default; for interface-specific fields, see the corresponding section.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| result | integer | Yes | Processing result.<ul><li>0: Success</li><li>Non-zero: Failure</li></ul> |
| result_message | string | Yes | Result description message. |

## Set Work Mode

The aircraft sets the speaker work mode (TTS text-to-speech / voice file). After updating the work mode, the payload returns the processing result in the response.

Related feature section: <a href="../function-set/speaker.html#set-work-mode" target="_blank" rel="noopener noreferrer">Set Work Mode</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: aircraft → payload
- **QoS**: 0
- **method**: `speaker_set_work_mode`
- **Corresponding interface**: `SpeakerImpl_OnSetWorkMode()`

```json
{
  "seq": 1,
  "method": "speaker_set_work_mode",
  "data": {
    "work_mode": 1
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters); the `data` field description is as follows:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| work_mode | integer | Yes | Work mode.<ul><li>0: TTS (text-to-speech)</li><li>1: voice (voice file)</li></ul> |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: payload → aircraft

```json
{
  "seq": 1,
  "method": "speaker_set_work_mode",
  "data": {
    "result": 0,
    "result_message": "success"
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters); there are no interface-specific fields in `data`.

## Start Audio Transfer

The aircraft starts transferring an audio file to the payload, declaring the file type, uuid, file name, and decode bitrate. After creating a temporary file and entering the transfer state, the payload returns the processing result in the response.

Related feature section: <a href="../function-set/speaker.html#start-audio-transfer" target="_blank" rel="noopener noreferrer">Start Audio Transfer</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: aircraft → payload
- **QoS**: 0
- **method**: `speaker_trans_start`
- **Corresponding interface**: `SpeakerImpl_OnTransStart()`

```json
{
  "seq": 6,
  "method": "speaker_trans_start",
  "data": {
    "file_type": 1,
    "uuid": "1a2b3c4d",
    "file_name": "alarm.opus",
    "decode_bitrate": 16000
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters); the `data` field description is as follows:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| file_type | integer | Yes | File type.<ul><li>0: tts_txt</li><li>1: opus</li><li>2: wav</li></ul> |
| uuid | string | Yes | The unique identifier of this transfer. |
| file_name | string | Yes | Original file name. |
| decode_bitrate | integer | Yes | Decode bitrate; optional values 8000/16000/24000/32000/48000/64000. |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: payload → aircraft

```json
}
```

### Response Field Description

## Transfer Audio Data Packet

The aircraft transfers audio binary data to the payload packet by packet. The data field is encoded as a hex string, which the payload-side SDK automatically decodes into binary; the payload writes to the file by offset in the callback.

Related feature section: <a href="../function-set/speaker.html#transfer-audio-data-packet" target="_blank" rel="noopener noreferrer">Transfer Audio Data Packet</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: aircraft → payload
- **QoS**: 0
- **method**: `speaker_trans_data`
- **Corresponding interface**: `SpeakerImpl_OnTransData()`

```json
{
  "seq": 7,
  "method": "speaker_trans_data",
  "data": {
    "packet_index": 0,
    "offset": 0,
    "data": "deadbeef"
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters); the `data` field description is as follows:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| packet_index | integer | Yes | Packet index. |
| offset | integer | Yes | The byte offset of this packet in the file. |
| data | string | Yes | The audio binary data of this packet, encoded as a hex string. |

:::warning Warning:
The data field is a hex string, and the payload-side SDK automatically decodes it into binary. What the payload receives in the callback is already decoded binary data, and no further hex decoding is needed.
:::

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: payload → aircraft

```json
{
  "seq": 7,
  "method": "speaker_trans_data",
  "data": {
    "result": 0,
    "result_message": "success"
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters); there are no interface-specific fields in `data`.

## Finish Audio Transfer

The aircraft finishes the audio transfer, carrying the MD5 of the whole file. The payload calculates the MD5 of the received file and compares it with the requested value; if they match, it saves as the official file; otherwise, it returns a failure in the response, notifying the aircraft to retransmit.

Related feature section: <a href="../function-set/speaker.html#finish-audio-transfer" target="_blank" rel="noopener noreferrer">Finish Audio Transfer</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: aircraft → payload
- **QoS**: 0
- **method**: `speaker_trans_finish`
- **Corresponding interface**: `SpeakerImpl_OnTransFinish()`

```json
{
  "seq": 8,
  "method": "speaker_trans_finish",
  "data": {
    "md5": "9e107d9d372bb6826bd81d3542a419d6"
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters); the `data` field description is as follows:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| md5 | string | Yes | The MD5 of the whole file (32-character hex), used to verify transfer integrity. |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: payload → aircraft

```json
{
  "seq": 8,
```

## Speaker State Push

The payload pushes the current speaker state.

Related feature section: <a href="../function-set/speaker.html#speaker-state-push" target="_blank" rel="noopener noreferrer">Speaker State Push</a>.

### Payload Example

- **Topic**: `thing/product/{client_id}/state`
- **Direction**: payload → aircraft
- **QoS**: 0
- **method**: `speaker_state`
- **Corresponding interface**: `Speaker_PublishState()`

```json
{
  "seq": 100,
  "method": "speaker_state",
  "data": {
    "system_state": 2,
    "work_mode": 1,
    "play_mode": 0,
    "play_volume": 50,
    "play_file_name": "alarm.opus",
    "play_file_uuid": "1a2b3c4d"
  }
}
```

### Field Description

For the top-level fields, see [Request Parameters](#request-parameters); the `data` field description is as follows:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| system_state | integer | Yes | System state.<ul><li>0: idle</li><li>1: transmitting</li><li>2: playing</li><li>3: error</li><li>4: tts_conversion (TTS converting)</li></ul> |
| work_mode | integer | Yes | Work mode.<ul><li>0: TTS (text-to-speech)</li><li>1: voice (voice file)</li></ul> |
| play_mode | integer | Yes | Play mode.<ul><li>0: single</li><li>1: loop</li></ul> |
| play_volume | integer | Yes | Current volume, 0~100. |
| play_file_name | string | Yes | Current playing file name. |
| play_file_uuid | string | Yes | Current playing file uuid. |
