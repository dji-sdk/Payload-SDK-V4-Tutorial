This section defines the MQTT interfaces of the custom widget feature, covering the MQTT payload structures and field descriptions for getting the widget file list, setting a widget value, getting a widget value, pushing widget status, and pushing floating window messages.

:::tip Note:
- The C interfaces in PSDK encapsulate the MQTT protocol described in this section. When developing with PSDK, you do not need to handle MQTT messages directly. Refer to these protocol definitions only if you need to implement the protocol yourself or debug and verify the underlying messages. For the feature overview and C interface examples, see <a href="../function-set/custom-widget.html" target="_blank" rel="noopener noreferrer">Function Set - Custom Widget</a>.
- Before using this feature, the payload device must first complete access and authentication. For the access protocol, see <a href="api-access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Protocol Description

The topics involved in the interface are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| service request | Aircraft → Payload | thing/product/{client_id}/services |
| service response | Payload → Aircraft | thing/product/{client_id}/services_reply |
| state push | Payload → Aircraft | thing/product/{client_id}/state |

- `{client_id}` is the payload device serial number.
- **QoS**: 0.

The interfaces supported by this module are as follows:

| method | Type | Purpose | Corresponding C interface |
|:---|:---|:---|:---|
| widget_get_file_list | service | The aircraft gets the widget configuration file list | WidgetImpl_OnGetFileList() |
| widget_set_value | service | The aircraft sets a widget value | WidgetImpl_OnSetValue() |
| widget_get_value | service | The aircraft gets a widget value | WidgetImpl_OnGetValue() |
| widget_state | state | The payload pushes the widget status | Widget_PublishState() |
| widget_float_window_msg | state | The payload pushes a float window message | Widget_PublishFloatWindowMsg() |

## Common Parameters

The following parameters are the common top-level parameters shared by the messages of all custom widget interfaces, and are not repeated in the field descriptions of each interface.

### Request Parameters

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| seq | integer | Yes | Request sequence number; echoed back unchanged in the response, used to match the request with the response. |
| method | string | Yes | Method identifier; for values, see the description of each interface. |
| data | object | Yes | Service data body; `{}` when there are no service parameters. |

### Response Parameters

The top-level fields of the response are the same as those of the request. By default, `data` contains the following common fields; interface-specific fields are described in the corresponding section.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| result | integer | Yes | Processing result.<ul><li>0: Success</li><li>Non-zero: Failure</li></ul> |
| result_message | string | Yes | Result description message. |

## Get Widget File List

The aircraft requests the widget configuration file list from the payload according to the App's current language and screen type; the payload returns it in the response, and the aircraft can determine whether it needs to download an update based on `md5`.

Related feature section: <a href="../function-set/custom-widget.html#get-widget-file-list" target="_blank" rel="noopener noreferrer">Get Widget File List</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: Aircraft → Payload
- **QoS**: 0
- **method**: `widget_get_file_list`
- **Corresponding interface**: `WidgetImpl_OnGetFileList()`

```json
{
  "seq": 1,
  "method": "widget_get_file_list",
  "data": {
    "language": 1,
    "screen_type": 0
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters). The `data` fields are described below:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| language | integer | Yes | Current system language of the App.<ul><li>0: English</li><li>1: Simplified Chinese</li><li>2: Japanese</li><li>3: French</li></ul> |
| screen_type | integer | Yes | Current screen type of the App.<ul><li>0: Large screen</li><li>1: Small screen</li></ul> |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: Payload → Aircraft

```json
{
  "seq": 1,
  "method": "widget_get_file_list",
  "data": {
    "result": 0,
    "result_message": "success",
    "file_list": [
      {
        "file_index": 0,
        "file_name": "widget_config.json",
        "file_size": 2048,
        "md5": "9e107d9d372bb6826bd81d3542a419d6"
      }
    ]
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters). The `data` fields are described below:

<div class="collapsible" />

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| file_list | array&lt;object&gt; | Yes | Widget configuration file list. |
| >>file_index | integer | Yes | File index. |
| >>file_name | string | Yes | File name, such as `widget_config.json`. |
| >>file_size | integer | Yes | File size, in bytes. |
| >>md5 | string | Yes | File MD5, used for verification and to determine whether an update is needed. |

## Set Widget Value

The aircraft sets the value of a specified widget. After updating the widget status, the payload returns the processing result in the response.

Related feature section: <a href="../function-set/custom-widget.html#set-widget-value" target="_blank" rel="noopener noreferrer">Set Widget Value</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: Aircraft → Payload
- **QoS**: 0
- **method**: `widget_set_value`
- **Corresponding interface**: `WidgetImpl_OnSetValue()`

```json
{
  "seq": 2,
  "method": "widget_set_value",
  "data": {
    "widget_index": 2,
    "widget_type": 2,
    "widget_value": 1
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters). The `data` fields are described below:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| widget_index | integer | Yes | Widget index. |
| widget_type | integer | Yes | Widget type.<ul><li>1: Button</li><li>2: Switch</li><li>3: Scale (slider)</li><li>4: List</li><li>5: IntInputBox (integer input box)</li></ul> |
| widget_value | integer | Yes | Widget value. |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: Payload → Aircraft

```json
{
  "seq": 2,
  "method": "widget_set_value",
  "data": {
    "result": 0,
    "result_message": "success"
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters). There are no interface-specific fields in `data`.

## Get Widget Value

The aircraft reads the current value of a specified widget. The payload echoes the widget index and returns the current value in the response.

Related feature section: <a href="../function-set/custom-widget.html#get-widget-value" target="_blank" rel="noopener noreferrer">Get Widget Value</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: Aircraft → Payload
- **QoS**: 0
- **method**: `widget_get_value`
- **Corresponding interface**: `WidgetImpl_OnGetValue()`

```json
{
  "seq": 3,
  "method": "widget_get_value",
  "data": {
    "widget_index": 2
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters). The `data` fields are described below:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| widget_index | integer | Yes | Widget index. |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: Payload → Aircraft

```json
{
  "seq": 3,
  "method": "widget_get_value",
  "data": {
    "result": 0,
    "result_message": "success",
    "widget_index": 2,
    "widget_value": 1
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters). The `data` fields are described below:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| widget_index | integer | Yes | Widget index (echoes the index in the request). |
| widget_value | integer | Yes | Current value of the widget. |

## Widget State Push

The payload pushes the current status of all widgets.

Related feature section: <a href="../function-set/custom-widget.html#widget-state-push" target="_blank" rel="noopener noreferrer">Widget State Push</a>.

### Payload Example

- **Topic**: `thing/product/{client_id}/state`
- **Direction**: Payload → Aircraft
- **QoS**: 0
- **method**: `widget_state`
- **Corresponding interface**: `Widget_PublishState()`

```json
{
  "seq": 4,
  "method": "widget_state",
  "data": {
    "widget_list": [
      {
        "widget_index": 2,
        "widget_type": "switch",
        "widget_value": 1
      }
    ]
  }
}
```

### Field Description

For the top-level fields, see [Request Parameters](#request-parameters). The `data` fields are described below:

<div class="collapsible" />

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| widget_list | array&lt;object&gt; | Yes | Widget status list. |
| >>widget_index | integer | Yes | Widget index. |
| >>widget_type | string | Yes | Widget type.<ul><li>button</li><li>list</li><li>switch</li><li>scale</li><li>int_input_box</li></ul> |
| >>widget_value | integer | Yes | Current value of the widget. |

## Float Window Message Push

The payload pushes the text message displayed in the float window.

Related feature section: <a href="../function-set/custom-widget.html#float-window-message-push" target="_blank" rel="noopener noreferrer">Float Window Message Push</a>.

### Payload Example

- **Topic**: `thing/product/{client_id}/state`
- **Direction**: Payload → Aircraft
- **QoS**: 0
- **method**: `widget_float_window_msg`
- **Corresponding interface**: `Widget_PublishFloatWindowMsg()`

```json
{
  "seq": 5,
  "method": "widget_float_window_msg",
  "data": {
    "message": "payload status: OK"
  }
}
```

### Field Description

For the top-level fields, see [Request Parameters](#request-parameters). The `data` fields are described below:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| message | string | Yes | Text message displayed in the float window. |
