This section defines the MQTT interface of the data subscription feature, covering the MQTT payload structures and field descriptions for subscribing to a topic, unsubscribing, querying the latest value, and pushing flight control data.

:::tip Note:
- The C interfaces in PSDK encapsulate the MQTT protocol described in this section. When developing with PSDK, you do not need to handle MQTT messages directly. Refer to these protocol definitions only if you need to implement the protocol yourself or debug and verify the underlying messages. For the feature overview and C interface examples, see <a href="../function-set/fc-subscription.html" target="_blank" rel="noopener noreferrer">Function Set - Data Subscription</a>.
- Before using this feature, the payload device must first complete access and authentication. For the access protocol, see <a href="api-access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Protocol Description

The topics involved in the interface are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| service request | Payload → Aircraft | thing/product/{client_id}/services |
| service response | Aircraft → Payload | thing/product/{client_id}/services_reply |
| osd push | Aircraft → Payload | thing/product/{client_id}/osd |

- `{client_id}` is the payload device serial number.
- **QoS**: 0.

The interfaces supported by this module are as follows:

| method | Type | Purpose | Corresponding C interface |
|:---|:---|:---|:---|
| fc_subscribe_topic | service | The payload subscribes to a specified topic and sets the push frequency | DataSubscription_SubscribeTopic() |
| fc_unsubscribe_topic | service | The payload unsubscribes from a specified topic | DataSubscription_UnsubscribeTopic() |
| fc_get_latest_value | service | The payload queries the latest value of a specified topic | DataSubscription_GetLatestValue() |
| fc_publish_data | osd | The flight controller pushes data of a subscribed topic to the payload | DataSubscription_OnPublishData() |

:::warning Warning:
The query result of `fc_get_latest_value` is returned in the `data` of the service response (services_reply); the corresponding topic must be subscribed before querying. When subscribing to a large number of topics in bulk, send them in batches and control the sending pace, to avoid a large number of requests piling up in a short time, which may cause subscription failures or timeouts.
:::

## Common Parameters

The following parameters are the common top-level parameters shared by the messages of all data subscription interfaces, and are not repeated in the field descriptions of each interface.

### Request Parameters

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| seq | integer | Yes | Request sequence number; echoed back unchanged in the response, used to match the request with the response. |
| method | string | Yes | Method identifier; for values, see the description of each interface. |
| data | object | Yes | Service data body; `{}` when there are no service parameters. |

### Response Parameters

The top-level fields of the response are the same as those of the request. By default, `data` contains the following common fields; interface-specific fields are described in the corresponding section.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| result | integer | Yes | Processing result.<ul><li>0: Success</li><li>Non-zero: Failure</li></ul> |
| result_message | string | Yes | Result description message. |

## Subscribe to a Topic

The payload subscribes to a specified flight controller telemetry topic and sets the push frequency. After the subscription succeeds, the flight controller pushes the topic data at the `frequency` frequency. Subscribing to the same topic again updates the frequency, with the new frequency overriding the old subscription.

Related feature section: <a href="../function-set/fc-subscription.html#subscribe-to-a-topic" target="_blank" rel="noopener noreferrer">Subscribe to a Topic</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: Payload → Aircraft
- **QoS**: 0
- **method**: `fc_subscribe_topic`
- **Corresponding interface**: `DataSubscription_SubscribeTopic()`

```json
{
  "seq": 1,
  "method": "fc_subscribe_topic",
  "data": {
    "topic": "quaternion",
    "frequency": 10
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters). The `data` fields are described below:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| topic | string | Yes | Topic name; for values, see [Subscription Topic List](#subscription-topic-list), such as `quaternion`. |
| frequency | integer | Yes | Frequency at which the flight controller pushes the topic data, in Hz.<ul><li>1: 1 Hz</li><li>5: 5 Hz</li><li>10: 10 Hz</li><li>50: 50 Hz</li></ul> |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: Aircraft → Payload

```json
{
  "seq": 1,
  "method": "fc_subscribe_topic",
  "data": {
    "result": 0,
    "result_message": "success"
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters). There are no interface-specific fields in `data`.

## Flight Control Data Push

The flight controller pushes data at each topic's subscription frequency, with different topics belonging to different messages. The `data` of each message contains only the key corresponding to the current topic.

Related feature section: <a href="../function-set/fc-subscription.html#receive-push-data" target="_blank" rel="noopener noreferrer">Receive Push Data</a>.

### Payload Example

- **Topic**: `thing/product/{client_id}/osd`
- **Direction**: Aircraft → Payload
- **QoS**: 0
- **method**: `fc_publish_data`
- **Corresponding interface**: `DataSubscription_OnPublishData()`

The following example is a push message for the `velocity` topic; the actual pushed key depends on the topic currently being pushed.

```json
{
  "seq": 100,
  "method": "fc_publish_data",
  "data": {
    "velocity": { "x": 0.1, "y": -0.2, "z": 0.0, "health": 1 }
  }
}
```
