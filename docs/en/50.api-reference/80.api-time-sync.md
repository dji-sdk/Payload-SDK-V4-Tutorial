This section defines the MQTT interfaces of the time synchronization feature, covering the MQTT payload structures and field descriptions for setting the signal mode and pushing UTC time.

:::tip Note:
- The C interfaces in PSDK encapsulate the MQTT protocol described in this section. When developing with PSDK, you do not need to handle MQTT messages directly. Refer to these protocol definitions only if you need to implement the protocol yourself or debug and verify the underlying messages. For the feature overview and C interface examples, see <a href="../function-set/time-sync.html" target="_blank" rel="noopener noreferrer">Function Set - Time Synchronization</a>.
- Before using this feature, the payload device must first complete Access and Authentication. For the access protocol, see <a href="api-access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Protocol Description

The Topics involved in the interfaces are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| service request | payload → aircraft | thing/product/{client_id}/services |
| service response | aircraft → payload | thing/product/{client_id}/services_reply |
| event push | aircraft → payload | thing/product/{client_id}/events |

- `{client_id}` is the payload device serial number.
- **QoS**: 0.

The interfaces supported by this module are as follows:

| method | Type | Purpose | Corresponding C interface |
|:---|:---|:---|:---|
| time_sync_set_signal_mode | service | The payload sets the time synchronization signal mode (FTS/PPS) | TimeSync_SetSignalMode() |
| time_sync | event | The aircraft pushes UTC time to the payload | TimeSync_OnSync() |

:::warning Warning:
UTC time is only pushed by the aircraft when the signal mode is PPS. After the payload calls `time_sync_set_signal_mode` to set the mode to PPS, the aircraft starts to report UTC time via the `time_sync` event. The event method that reports UTC time is `time_sync`, which is distinct from the service method `time_sync_set_signal_mode` used to set the signal mode.
:::

## Common Parameters

The following parameters are the top-level common parameters shared by the messages of all time synchronization interfaces, and are not listed repeatedly in the field descriptions of each interface.

### Request Parameters

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| seq | integer | Yes | Request sequence number; echoed back unchanged in the response, used to match the request with the response. |
| method | string | Yes | Method identifier; for values, see each interface description. |
| data | object | Yes | Service data body; `{}` when there are no service parameters. |

### Response Parameters

The top-level fields of the response are the same as those of the request. `data` contains the following common fields by default; interface-specific fields are described in the corresponding sections.

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| result | integer | Yes | Processing result.<ul><li>0: Success</li><li>Non-zero: Failure</li></ul> |
| result_message | string | Yes | Result description message. |

## Set Time Synchronization Signal Mode

The payload sets the time synchronization signal source. After selecting PPS, the aircraft starts pushing UTC time periodically; after selecting FTS (default), it stops pushing.

Related feature section: <a href="../function-set/time-sync.html#set-time-synchronization-signal-mode" target="_blank" rel="noopener noreferrer">Set Time Synchronization Signal Mode</a>.

### Request Payload Example

- **Topic**: `thing/product/{client_id}/services`
- **Direction**: payload → aircraft
- **QoS**: 0
- **method**: `time_sync_set_signal_mode`
- **Corresponding interface**: `TimeSync_SetSignalMode()`

```json
{
  "seq": 1,
  "method": "time_sync_set_signal_mode",
  "data": {
    "mode": 1
  }
}
```

### Request Field Description

For the top-level fields, see [Request Parameters](#request-parameters). The `data` fields are described as follows:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| mode | integer | Yes | Time synchronization signal mode.<ul><li>0: FTS signal (default)</li><li>1: PPS signal</li></ul> |

### Response Payload Example

- **Topic**: `thing/product/{client_id}/services_reply`
- **Direction**: aircraft → payload

```json
{
  "seq": 1,
  "method": "time_sync_set_signal_mode",
  "data": {
    "result": 0,
    "result_message": "success"
  }
}
```

### Response Field Description

For the top-level fields, see [Response Parameters](#response-parameters). There are no interface-specific fields in `data`.

## Receive UTC Time

When the signal mode is PPS, the aircraft pushes the current UTC time periodically.

Related feature section: <a href="../function-set/time-sync.html#receive-utc-time" target="_blank" rel="noopener noreferrer">Receive UTC Time</a>.

### Payload Example

- **Topic**: `thing/product/{client_id}/events`
- **Direction**: aircraft → payload
- **QoS**: 0
- **method**: `time_sync`
- **Corresponding interface**: `TimeSync_OnSync()`

```json
{
  "seq": 1,
  "method": "time_sync",
  "data": {
    "year": 2021,
    "month": 1,
    "day": 1,
    "hour": 2,
    "minute": 0,
    "second": 0,
    "nano_second": 0
  }
}
```

### Field Description

For the top-level fields, see [Request Parameters](#request-parameters). The `data` fields are described as follows:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| year | integer | Yes | Year. |
| month | integer | Yes | Month, value 1~12. |
| day | integer | Yes | Day, value 1~31. |
| hour | integer | Yes | Hour, value 0~23. |
| minute | integer | Yes | Minute, value 0~59. |
| second | integer | Yes | Second, value 0~59. |
| nano_second | integer | Yes | Nanosecond, value 0~999999999. |
