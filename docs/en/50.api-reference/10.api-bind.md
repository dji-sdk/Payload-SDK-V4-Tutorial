This section defines the MQTT interface of the application binding feature, covering the MQTT payload structure and field descriptions of the `bind_required` event.

:::tip Note:
- The C interfaces in PSDK encapsulate the MQTT protocol described in this section. When developing with PSDK, you do not need to handle MQTT messages directly. Refer to these protocol definitions only if you need to implement the protocol yourself or debug and verify the underlying messages. For the feature overview and C interface examples, see <a href="../function-set/bind.html" target="_blank" rel="noopener noreferrer">Function Set - Binding Status Notification</a>.
- Before using this feature, the payload device must first complete access and authentication. For the access protocol, see <a href="api-access-authentication.html" target="_blank" rel="noopener noreferrer">Access and Authentication</a>.
:::

## Protocol Description

The topics involved in the interface are as follows:

| Type | Direction | Topic |
|:---|:---|:---|
| event push | Aircraft → Payload | thing/product/{client_id}/events |

- `{client_id}` is the payload device serial number.
- **QoS**: 0.

The interfaces supported by this module are as follows:

| method | Type | Purpose | Corresponding C interface |
|:---|:---|:---|:---|
| bind_required | event | The aircraft notifies that the device is not bound and must complete binding via DJI Assistant 2 | Received after subscribing with bind_monitor_start() |

## Common Parameters

### Event Push Parameters

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| seq | integer | Yes | Message sequence number. |
| method | string | Yes | Fixed as `bind_required`. |
| data | object | Yes | Service data body; see the field descriptions of each interface. |

## bind_required Event

When the aircraft detects that the device is not bound, it proactively pushes `bind_required` on the event channel, carrying the current binding status, a status description, and an operation hint, to notify the payload to complete the binding process via DJI Assistant 2. If the device is in the unbound state after connecting to the MQTT server, the aircraft keeps pushing this event until binding is complete. During this push period, the aircraft usually rejects all service requests initiated by the payload.

Related feature section: <a href="../function-set/bind.html#start-monitoring" target="_blank" rel="noopener noreferrer">Start Monitoring</a>.

### Payload Example

- **Topic**: `thing/product/{client_id}/events`
- **Direction**: Aircraft → Payload
- **QoS**: 0
- **method**: `bind_required`
- **Corresponding interface**: Passively received after subscribing with `bind_monitor_start()`

```json
{
  "seq": 0,
  "method": "bind_required",
  "data": {
    "bind_state": 3,
    "bind_state_desc": "BINDING",
    "message": "Binding in progress. Waiting for DA2 to complete binding.",
    "timestamp_ms": 1716393600000
  }
}
```

### Field Description

For the top-level fields, see [Event Push Parameters](#event-push-parameters). The `data` fields are described below:

| Field | Type | Required | Description |
|:---|:---|:---|:---|
| bind_state | integer | Yes | Current binding status.<ul><li>0: Idle, binding check not yet started</li><li>1: Querying binding status</li><li>2: Bound</li><li>3: Binding, waiting for DJI Assistant 2 to complete binding</li><li>4: Binding succeeded</li><li>5: Binding failed</li><li>6: Waiting for DJI Assistant 2 to complete unbinding</li><li>7: Unbinding succeeded</li><li>8: Unbinding failed</li></ul> |
| bind_state_desc | string | Yes | Binding status description string, such as "BINDING". |
| message | string | Yes | Operation hint message, such as "Binding in progress. Waiting for DJI Assistant 2 to complete binding.". |
| timestamp_ms | integer | Yes | Timestamp when the aircraft sends the message, in milliseconds. |
